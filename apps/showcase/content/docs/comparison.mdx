This page compares Time with two React calendars that many teams already use:
[FullCalendar](https://fullcalendar.io) 7.1, through `@fullcalendar/react` and its premium
plugins, and [react-big-calendar](https://github.com/bigcalendar/react-big-calendar) 1.20. It's
accurate as of **October 2026**. Claims about Time come from these docs and the code on `main`.
Claims about the other two link their sources in the notes at the end of the page; a ✗ without a
note means we found no such feature in their docs or code. If something here is wrong or out of
date, [open an issue](https://github.com/Moltenship/time/issues).

<Callout type="warn" title="Time is new, pre-1.0, and not on npm yet">
  Time started in August 2026 and has one maintainer. Its packages haven't been published, so until
  the first release you [run it from source](/docs/installation#run-from-source), and its API will
  change before 1.0. FullCalendar has been developed since 2009 and react-big-calendar since 2015.
  Both are downloaded more than a million times a week and run in production in many apps. Read the
  rows below with that in mind.
</Callout>

**✓** means built in. **Partial** means it's there, with the limit the note gives. **✗** means
it isn't built in: you'd write it yourself or add another library.

### How the sizes were measured

Each library rendered the same calendar from one entry file: month, week, day and agenda (or list)
views, the library's toolbar, and dragging, resizing and creating turned on, in the Europe/Berlin
time zone. For Time, that's the [Quick start](/docs/quick-start)'s calendar with `onEventChange` and
the `Announcer` added, built from the registry source that `shadcn add` copies, at commit
`62b24df6`. FullCalendar used its classic theme. react-big-calendar used its Luxon localizer, since
its date-fns localizer can't take a time zone, and its drag-and-drop addon, imported from
`react-big-calendar/lib/addons/dragAndDrop` as its docs show; that path is CommonJS and brings a
second copy of some modules. Each entry was bundled with esbuild 0.28.2
(`--bundle --minify --format=esm --target=es2022`), with React and React DOM left out and CSS not
counted, then compressed with `gzip -9`. A kB is 1,000 bytes.

| Bundle                                                                                 | Minified | Minified and gzipped |
| -------------------------------------------------------------------------------------- | -------- | -------------------- |
| Time: week, day, month and agenda, with the toolbar and the shadcn components they use | 430 kB   | 142.4 kB             |
| The same, without Base UI, Floating UI, `cn` and lucide-react                          | 217 kB   | 67.2 kB              |
| Time with resource columns and the resource timeline added                             | 481 kB   | 157.5 kB             |
| The same, without Base UI, Floating UI, `cn` and lucide-react                          | 268 kB   | 82.0 kB              |
| `temporal-polyfill/global` 1.0.6, for browsers without Temporal                        | 59 kB    | 20.5 kB              |
| FullCalendar 7.1.2: month, week, day and list, with interaction                        | 301 kB   | 84.3 kB              |
| FullCalendar 7.1.2 with premium resource timeline and resource time grid               | 429 kB   | 118.0 kB             |
| react-big-calendar 1.20.0 with drag and drop and Luxon 3.7                             | 323 kB   | 98.6 kB              |
| react-big-calendar 1.20.0 with drag and drop and date-fns 4.4, without time zones      | 288 kB   | 84.9 kB              |

Time's views are the largest of the three. About half of their minified size is the shadcn
components they're built on: Base UI's select, popover and tooltip, with Floating UI. An app that
already uses those through shadcn/ui ships that code already, which is what the "without" rows show.
FullCalendar's numbers include the parts of `temporal-polyfill` it imports. Time's don't include a
polyfill, which only browsers without Temporal need.

## When to choose which

**FullCalendar** if you need a calendar you can rely on in production today, if your app uses Vue,
Angular or no framework, if you need many locales out of the box, or if you want a vendor with paid
support. Its premium views cost money, but less than building a scheduler. Its React package has
been written in React since 7.0, renders on the server, handles named time zones through Temporal
and has shadcn themes, so none of those set Time apart.

**react-big-calendar** if you want a free MIT calendar with month, week, day and agenda views and
drag and drop, and you don't need a year view, a timeline, keyboard editing, recurring events or
time zones beyond a localizer's default. It had two releases in the last twelve months, so expect
fixes to come slowly.

**Time** if you're on React 19 and can start on a pre-1.0 library run from source, and you want
Temporal from end to end, view components you own as source, editing by keyboard with screen reader
announcements, edits to recurring series, availability and conflict rules, or resource views under
the MIT license. Don't choose it yet if you need a stable API, a published package, or a framework
other than React.
