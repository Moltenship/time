---
title: Solid views from the registry
description: Add the styled Solid agenda, its theme and its shared parts to a Solid 2.0 app with the shadcn CLI, as source files you own.
---

The styled views for Solid are source files you add to your app and then own. They install with
the shadcn CLI from this site's Solid registry, at `https://time.molten.sh/r/solid`. The registry
has four items:

| Item             | What it adds                                                                         |
| ---------------- | ------------------------------------------------------------------------------------ |
| `base-tokens`    | shadcn/ui's neutral tokens for light and dark, for an app without them               |
| `calendar-theme` | The calendar's color tokens and its event colors, in `event-colors.ts`               |
| `calendar`       | The event chip, event names, the views' key map and the icons, which the views share |
| `list-view`      | The [agenda](/docs/solid/agenda)                                                     |

`list-view` brings `calendar` and `calendar-theme` with it. An app with its own shadcn/ui-style
theme, which defines `--background`, `--border`, `--primary` and the rest, skips `base-tokens`.

<Steps>
<Step>

### Install the packages

Install `@moltenship/calendar-solid` and its peers, as [the Solid page](/docs/api/solid#install)
describes. It's the one package of ours a Solid app needs: it re-exports the engine and the
`Temporal` utilities, and the registry's files import from it alone.

```bash
pnpm add @moltenship/calendar-solid@next solid-js @solidjs/web @ui-sdk/core @ui-sdk/solid
```

Time 2.0 is a pre-release on npm's `next` tag, so the command installs `@next`. `shadcn add` adds
the packages the files import, `@tanstack/virtual-core` among them, if your app doesn't have them
yet.

</Step>
<Step>

### Set up Tailwind CSS 4

The files style themselves with Tailwind classes, so the app needs Tailwind CSS 4 and its
preflight. With Vite, add `@tailwindcss/vite` beside Solid's plugin:

```ts title="vite.config.ts"
import solid from "@solidjs/vite-plugin";
import tailwindcss from "@tailwindcss/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [solid(), tailwindcss()],
  resolve: { tsconfigPaths: true },
});
```

Import Tailwind in your global stylesheet, below an `@layer ui-sdk;` that puts your styles after
the CSS ui-sdk adds to the page, and make Tailwind's `dark:` variant follow a `.dark` ancestor, as
the theme does:

<include meta='title="src/app.css"'>../../../../../tools/registry/consumers/solid/app.css</include>

The files import each other through the `@/` alias, so map it in `tsconfig.json`:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "jsx": "preserve",
    "jsxImportSource": "@solidjs/web",
    "lib": ["DOM", "DOM.Iterable", "ESNext"],
    "paths": { "@/*": ["./src/*"] }
  }
}
```

</Step>
<Step>

### Point the shadcn CLI at the Solid registry

The CLI has no Solid template to `init` from, so write `components.json` at the app's root
yourself. `registries` names the Solid registry, so `@moltenship/<item>` installs the Solid items,
and `tailwind.css` names the stylesheet the theme's tokens go into:

<include meta='title="components.json"'>
  ../../../../../tools/registry/consumers/solid/components.json
</include>

</Step>
<Step>

### Add the items

```bash
npx shadcn@latest add @moltenship/base-tokens @moltenship/list-view
```

Without `registries` in `components.json`, give the item's full URL instead:

```bash
npx shadcn@latest add https://time.molten.sh/r/solid/list-view.json
```

The CLI writes the tokens into `src/app.css` and the files under `components/calendar`:

```txt
src/components/calendar
├── event-colors.ts          calendar-theme
├── event-chip.tsx           calendar
├── event-chip.styles.ts
├── event-label.ts
├── event-names.ts
├── icons.tsx
├── preview-state.ts
├── view-keyboard.ts
├── view-keys.ts
└── list-view                list-view
    ├── agenda-view.tsx
    ├── agenda-list.tsx
    ├── agenda-day.tsx
    ├── agenda-item.tsx
    ├── agenda-states.tsx
    ├── agenda-rows.ts
    ├── agenda-labels.ts
    ├── agenda.styles.ts
    ├── agenda-virtualizer.ts
    └── use-agenda-virtualizer.ts
```

The `.styles.ts`, label, row, key map and virtualizer files are plain TypeScript. They're the same
files the React registry installs, so the Solid agenda looks, reads and moves as the React one
does.

</Step>

## Dark mode

The theme switches when an ancestor of the calendar has the `dark` class, as shadcn/ui does. Toggle
it on `<html>` from your app's theme setting. The `@custom-variant` line in `src/app.css` above
makes the files' `dark:` classes follow the same class.

[Theming](/docs/theming) lists the calendar's tokens and its event colors. They're the same in
Solid.

## Update the files

The files are copies you own: edit them as you would any component. A fix in the registry reaches
your app when you add the item again. The command writes the files your app doesn't have, skips
the ones that match, and asks before it replaces one that differs. `--dry-run` lists what it would
do, and `--diff` with a path from that list prints the difference, writing nothing:

```bash
npx shadcn@latest add @moltenship/list-view --dry-run
npx shadcn@latest add @moltenship/list-view --diff src/components/calendar/list-view/agenda-view.tsx
```

Each item that imports the calendar names the range of `@moltenship/calendar-solid` it's built
for, so the CLI installs a version the files compile against.
