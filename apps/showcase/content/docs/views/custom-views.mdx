A view has two halves:

- a **strategy**: four plain functions that pick the visible dates, move them, title them, and turn
  the events into whatever the view needs to draw (its **projection**);
- a **Renderer**: a React component that receives that projection.

`Root` runs the strategy and passes the result to the Renderer, so the Renderer only draws.

`projection` gets its type from `project`.

`anchor` is the date in the `anchorDate` state. `environment` holds `locale`, `timeZone`,
`secondaryTimeZones`, `weekRules`, `direction`, and `disambiguation`. The functions should be pure:
`Root` calls them during render and reuses the projection until one of its inputs changes.

`project` receives:

| Field          | Contents                                                                            |
| -------------- | ----------------------------------------------------------------------------------- |
| `snapshot`     | The validated, indexed events. Query it with `queryTimed` and friends.              |
| `range`        | The visible dates, from `getRange`                                                  |
| `instantRange` | The same dates as instants in the calendar's time zone, ready for `queryTimed`      |
| `loadRange`    | The dates to project: `getLoadRange`'s, or `range` without it. Always set by `Root` |
| `environment`  | Locale, time zone, secondary time zones, week rules, direction, disambiguation      |
| `resources`    | The `resources` prop                                                                |
| `options`      | The view's options after `viewOptions` overrides                                    |
| `today`        | Today's date in the calendar's time zone, or `null` before a clock is known         |

`today` is fixed when `Root` has `now`, so server and browser agree. Without `now` it's `null`
during server rendering and fills in after hydration.

### Typed events

Inside `project`, events are typed `unknown` unless you say otherwise, because a view can be used by
calendars with different records. To work with your own fields, annotate the input:

```ts
import type { CalendarViewProjectionInput } from "@moltenship/calendar";

project: ({ snapshot, instantRange }: CalendarViewProjectionInput<DaysOptions, Meeting>) =>
  snapshot.queryTimed(instantRange).map(({ event }) => event.title),
```

## Renderer

The Renderer is a regular component, so it can use hooks. It receives:

| Prop          | Contents                                                                                              |
| ------------- | ----------------------------------------------------------------------------------------------------- |
| `projection`  | What `project` returned                                                                               |
| `range`       | The visible dates                                                                                     |
| `loadRange`   | The dates `project` covered: `range`, or the strategy's wider `getLoadRange`                          |
| `options`     | The view's options                                                                                    |
| `environment` | Locale, time zone, secondary time zones, week rules, direction, disambiguation                        |
| `events`      | The snapshot `project` received, with [pending changes](/docs/interactions#pending-changes) applied   |
| `actions`     | `setAnchorDate`, `setView`, `navigateNext`, `navigatePrevious`, `navigateToday`, `proposeEventChange` |

`actions` never changes identity. `setView` takes any registered view name; an unknown name shows up
as an `unregistered-active-view` diagnostic. `proposeEventChange` and `events` are what a view needs
to let people [drag and resize events](/docs/interactions#drag-resize-and-create).

To declare a Renderer as its own component, type its props with `CalendarViewRendererProps`:

```tsx
import type { CalendarViewRendererProps } from "@moltenship/calendar";

function DaysRenderer({ projection }: CalendarViewRendererProps<DaysProjection, DaysOptions>) {
  // …
}
```

## Reading the view from other components

Components inside `Root` can read the active view without being part of it:

<include meta='title="days-view.tsx"'>../../examples/days-view.tsx#hooks</include>

- `Calendar.useVisibleRange()` returns the visible dates, or `null` when the active view isn't
  registered.
- `Calendar.useViewProjection()` returns the active view's `view` name, `definition`,
  `projection`, `range`, `instantRange`, `loadRange`, `loadInstantRange`, `options`,
  `environment`, and `events`, or `null`. Check `view` to
  narrow `projection` to that view's type.
- `useNow({ intervalMs })` returns the current instant for a now-line and re-renders on each tick.
  It's `null` during server rendering and hydration unless `Root` has `now`.
