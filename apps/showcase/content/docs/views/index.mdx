A view decides which dates are visible and how to draw them. A calendar can have several views, for
example a day view and a three-day view. The `view` state names the active one, and
`<Calendar.ActiveView />` renders it.

<Callout title="Built-in views are on the way">
  Month, week, day, and agenda views are in development and will get their own pages here. Until
  then, write your own. The [Quick start](/docs/quick-start) has a complete day view, and [Custom
  views](/docs/views/custom-views) covers the details.
</Callout>

## Registering views

Pass views to `createCalendar`. The first one is active by default unless you set `defaultView` or
`view` on `Root`. TypeScript learns the view names from this list, so `setView` and `defaultView`
only accept names you registered.

```tsx
const Calendar = createCalendar<Meeting>()({ eventAdapter, views: [dayView, daysView] });
```

Each name must be unique. `createCalendar` throws `calendar-duplicate-view-name` if two views share
one.

## View options

A view can declare `defaultOptions`. Override them per calendar with `viewOptions` on `Root`, keyed
by view name. Each entry is typed from that view's `defaultOptions`, and you only pass the fields you
want to change. For example, `viewOptions={{ days: { days: 5 } }}` makes the `days` view show five
days. [Custom views](/docs/views/custom-views#register-it-and-set-options) has the complete
example.

## Switching views

`ViewSwitcher` renders a `<select>` with one option per registered view:

```tsx
const labels = { day: "Day", days: "Several days" };

<Calendar.ViewSwitcher getViewLabel={(name) => labels[name]} />;
```

To build your own control, call `setView` from `useCalendarActions()`. Inside a view's Renderer, use
the `actions` prop instead.

The active view also drives `Title`, `PreviousTrigger`, and `NextTrigger`. The title comes from the
view's `getTitle`, and the buttons move by the view's own step: one day in a day view, three days in
a three-day view.

If the active name doesn't match a registered view, `ActiveView` renders its `fallback` prop, the
previous and next buttons are disabled, and `meta.diagnostics` includes an `unregistered-active-view`
error.
