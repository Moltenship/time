---
title: Undo toast
description: The Solid registry's toast that offers to undo each change to the calendar's events, and to redo each undo, with the keys for both.
---

Try it in the [Solid demo](https://moltenship-time-demo.vercel.app/solid/): move an event, and a
toast offers to undo the move.

The `calendar-history-toast` item shows an "Undo" toast after each change to the calendar's events,
and a "Redo" toast after an undo. It's the same toast as React's registry has, with the same
messages and keys, built on the [controls kit](/docs/views/controls)'s toast. It reads an event
history, the one `createEventHistory` makes and [Undo and redo](/docs/api/components#undo-and-redo)
describes.

## Add it

Add it with the shadcn CLI, as [UI source](/docs/installation#ui-source-optional) describes. It
brings the `calendar` item and the controls kit:

```bash
npx shadcn@latest add @moltenship/calendar-history-toast
```

## Use it

Record the calendar's committed changes into a history with `onEventChangeResult`, and render the
toast inside `Calendar.Root`, beside the `Announcer`:

<include meta='title="calendar-page.tsx"'>
  ../../examples/solid/calendar-page.tsx#undo-toast
</include>

An undo proposes the change back through `onEventChange`, so your app applies it as it would any
other: undoing a delete proposes a create that carries the deleted record. The toast also adds the
keys in the calendar's frame, Ctrl+Z to undo and Ctrl+Shift+Z or Ctrl+Y to redo, or ⌘Z and ⇧⌘Z on
a Mac, and speaks undo and redo through the `Announcer`.

| Prop            | Default                        | Effect                                                                 |
| --------------- | ------------------------------ | ---------------------------------------------------------------------- |
| `calendar`      | required                       | Your calendar, for its frame and event titles                          |
| `history`       | required                       | The history `onEventChangeResult` records into. Read once              |
| `messages`      | `calendarHistoryToastMessages` | What the toast says: English, in the item's file, to edit or translate |
| `announcements` | `calendarHistoryAnnouncements` | What the `Announcer` says after an undo or redo; `null` says nothing   |
| `shortcuts`     | the default keys               | `{ undo?, redo? }` to change them, `false` to turn them off            |
| `timeout`       | `6000`                         | How long a toast stays, in milliseconds                                |
| `class`         |                                | Classes for the toast's region, such as where it sits                  |

Undo and Redo buttons of your own, such as in the toolbar, take `useCalendarHistory` for
`canUndo`, `undo` and the rest. The toast already adds the keys, so they need no
`useCalendarHistoryShortcuts`.

## What it says

One toast shows at a time, and a cleared history closes it. A message that returns `null` shows no
toast and closes the one on screen: the English set does so for an empty stack or a change you
cancelled.

A screen reader reads each toast as it shows. Changes made by a gesture are announced as they're
made, so their toast's title follows that announcement. Deletes, updates and changes from your own
UI, which no gesture announced, add how to reach Undo after the title (`recordedHint`), and that
toast stays at least 10 seconds, long enough to hear it out. F6 moves focus to the toast's region
and back, Tab reaches its buttons, and Escape dismisses it. The region's name is `region`.

The toast's look comes from the kit's `toast.styles.ts`, the same file React's toast reads, and
`history-toast.styles.ts` beside the item. To use a toast of your own, see
[Use your own controls](/docs/views/controls#use-your-own-controls).
