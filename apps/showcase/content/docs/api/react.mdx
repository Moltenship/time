Everything on this page is exported from `@moltenship/calendar`.

## createCalendar

```ts
const Calendar = createCalendar<TEvent, TResource, TView, TSelection, TFocus>(options);
```

Creates a calendar: a set of components and hooks typed to your records. Call it once at module
scope. Type arguments are usually inferred from the options:

- `TEvent`: your event record.
- `TResource`: your resource record. Use `never` if you don't have resources.
- `TView`: the union of view names. Defaults to `string`.
- `TSelection`, `TFocus`: the types of the `selection` and `focus` state. Default to `string`.

Event and resource ID types come from the `id` field of your records when they have one.

views passed to `createCalendar`.

`Root` throws on its first render if it has no date (`calendar-root-requires-anchor-date`), no
time zone (`calendar-root-requires-time-zone`), or no view (`calendar-root-requires-view`).

## Components

Use these inside `Root`. Each renders one plain element with a `data-calendar-part` attribute and
accepts that element's usual props, including `className`, `style`, `ref`, and event handlers.

| Component         | Renders     | Notes                                                                       |
| ----------------- | ----------- | --------------------------------------------------------------------------- |
| `Frame`           | `<section>` | Outer wrapper. Gets the `{id}-frame` ID.                                    |
| `Toolbar`         | `<header>`  | Wrapper for controls.                                                       |
| `Title`           | `<span>`    | The active view's title, or its children. Gets the `{id}-title` ID.         |
| `PreviousTrigger` | `<button>`  | Moves back one step of the active view. Disabled when no view is active.    |
| `NextTrigger`     | `<button>`  | Moves forward one step of the active view.                                  |
| `TodayTrigger`    | `<button>`  | Moves to today in the calendar's time zone. Disabled without `now`/`clock`. |
| `ViewSwitcher`    | `<select>`  | One option per view. Requires `getViewLabel(name)`.                         |
| `Viewport`        | `<div>`     | Wrapper for the view. Gets the `{id}-viewport` ID.                          |
| `ActiveView`      | view output | Renders the active view, or `fallback` if it isn't registered.              |
| `CustomView`      | view output | Renders the view passed as `view`.                                          |
| `Event`           | your output | Looks up one event by `eventId` and calls `children` with it.               |

- The buttons default to `type="button"` and set `aria-controls` to the viewport. Give each one
  text or an `aria-label`.
- Your `onClick` or `onChange` runs first. Call `event.preventDefault()` in it to skip the built-in
  action.
- `Frame`, `Title`, and `Viewport` don't accept `id`. Set `id` on `Root` instead, so the IDs and
  `aria-controls` always match.

`Event` passes the record, its normalized form, and the calendar context:

```tsx
<Calendar.Event eventId="standup" fallback={<p>Not found</p>}>
  {({ event, normalized }) => (
    <p>
      {event.title} starts at {normalized.start.toString()}
    </p>
  )}
</Calendar.Event>
```

Using a component or hook outside `Root` throws `calendar-compound-component-outside-root` or
`calendar-hook-outside-root`.

## Hooks

| Hook                                   | Returns                                             |
| -------------------------------------- | --------------------------------------------------- |
| `useCalendar()`                        | `{ state, actions, meta }`                          |
| `useCalendarState()`                   | The six [state](/docs/concepts/state) values        |
| `useCalendarActions()`                 | The actions below. The object never changes.        |
| `useCalendarMeta()`                    | The [meta](#meta) object                            |
| `useCalendarSelector(selector, opts?)` | `selector(state)`. Re-renders only when it changes. |

`useCalendarSelector` compares results with `Object.is`. Pass `{ isEqual }` to compare another way.

### Actions

| Action                                 | Effect                                                 |
| -------------------------------------- | ------------------------------------------------------ |
| `setView(name)`                        | Changes the view                                       |
| `setAnchorDate(date)`                  | Changes the date                                       |
| `setTimeZone(zone)`                    | Changes the time zone                                  |
| `setSelection(value)`                  | Changes the selection (`null` clears it)               |
| `setFocus(value)`                      | Changes the focus (`null` clears it)                   |
| `setExpandedResourceIds(ids)`          | Changes the expanded resources                         |
| `navigatePrevious()`, `navigateNext()` | Moves by one step of the active view                   |
| `navigateToday()`                      | Moves to today. Does nothing without `now` or `clock`. |

Setting a value equal to the current one does nothing. Dates compare with `equals`, resource ID
arrays by their items in order, and selection and focus by identity.

## Diagnostics

Problems that don't stop rendering are collected in `meta.diagnostics` and passed to
`onDiagnosticsChange`. Time doesn't log them.

| `code`                     | `severity` | Cause                                                                                            |
| -------------------------- | ---------- | ------------------------------------------------------------------------------------------------ |
| `duplicate-view-name`      | warning    | Two views share a name. The last one is used.                                                    |
| `unregistered-active-view` | error      | The `view` state names a view that isn't registered.                                             |
| `invalid-event`            | error      | A record was skipped. `issue` has the details ([issue codes](/docs/api/events#invalid-records)). |

## View helpers

| Export                                    | Purpose                                                                                                        |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `defineCalendarView<TEvent, TResource>()` | Builds a view from a strategy and a Renderer. See [Custom views](/docs/views/custom-views#definecalendarview). |
| `createCalendarViewRegistry(views)`       | Builds the registry `Root` uses: `names`, `values`, `get`, `has`, `diagnostics`.                               |
| `createCalendarCapabilitySet(values)`     | Builds a capability set with `values` and `has(name)`.                                                         |
| `bindCalendarView(definition)`            | What `defineCalendarView` calls. Prefer `defineCalendarView`.                                                  |
