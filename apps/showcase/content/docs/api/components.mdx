## createCalendar

```ts
const Calendar = createCalendar<TEvent, TResource, TSelection, TFocus>()(options);
```

Creates a calendar: a set of components and hooks typed to your records. Call it once at module
scope. It's called twice: the first call takes your types, and the second infers the view names
from `views` and the ID types from the adapter.

- `TEvent`: your event record. Required.
- `TResource`: your resource record. Defaults to `unknown`; use `never` if you don't have resources.
- `TSelection`, `TFocus`: the types of the `selection` and `focus` state. Default to
  `CalendarSelection` and `CalendarFocus`, the days, slots, and events <React>the built-in views read and
  write. A calendar with only custom views can use its own types.</React><Solid>the keyboard hooks read and write. A calendar whose views bind no keyboard can use its own types.</Solid>

## defineCalendarView

```ts
const view = defineCalendarView({ name, defaultOptions, strategy, Renderer });
```

Defines a view. `defaultOptions` is required only when the strategy's options can't be `undefined`.
[Custom views](/docs/views/custom-views) covers the strategy, the projection input, and the
Renderer props. The related types are `CalendarViewStrategy`, `CalendarViewProjectionInput`, and
`CalendarViewRendererProps`.

`resolveViewInstantRange(range, timeZone)` turns visible dates into the instant range that `Root`
passes to `project` as `instantRange`, and `resolveViewLoadRange(strategy, anchor, environment,
options, range)` gives the `loadRange` it passes. Use them to run a strategy outside `Root`, for
example in a test.

`withAsciiSpaces(text)` writes the thin and narrow no-break spaces in `Intl` output as plain spaces.
Node.js and browsers disagree on them in date ranges, so wrap `formatRange` output that renders on
the server, as <React>the built-in titles and views do</React><Solid>the engine's titles do</Solid>, and hydration matches.

<React>

You can write most props inline. `locale`, `weekRules`, `secondaryTimeZones`, `availability`, `now`,
and a controlled `anchorDate`, `timeZone` or `view` are compared by value; `events`, `resources`,
`annotations`, `annotationSources` and a controlled `expandedResourceIds` are compared item by item;
`policies`, `onDiagnosticsChange`, and the change handlers are read from the latest render.
`viewOptions` is too, but the active view's options are compared one option at a time, so keep
functions and objects in them stable. A
`clock` object and a controlled `selection` or `focus` are compared by identity: keep them stable,
for example in state or at module scope.

`onVisibleRangeChange` reports each change once under Strict Mode too, and when a hidden `Activity`
is revealed. See [loading events](/docs/views/scrolling#loading-events-as-you-scroll) and
[TanStack Query](/docs/guides/tanstack-query).

</React>

<Solid>

Pass a signal's value for a prop that changes: `events={meetings()}`, `view={view()}`. You can
write most props inline. `locale`, `weekRules`, `secondaryTimeZones`, `availability`, `now`, and a
controlled `anchorDate`, `timeZone` or `view` are compared by value; `events`, `resources`,

them stable, in a signal or at module scope.

`Root` throws on its first render if it has no date (`calendar-root-requires-anchor-date`), no
time zone (`calendar-root-requires-time-zone`), or no view (`calendar-root-requires-view`).

## Components

Use these inside `Root`. Each renders one plain element with a `data-calendar-part` attribute and
accepts that element's usual props, including <React>`className`</React><Solid>`class`</Solid>, `style`, `ref`, and event handlers.

| Component         | Renders     | Notes                                                                                        |
| ----------------- | ----------- | -------------------------------------------------------------------------------------------- |
| `Frame`           | `<section>` | Outer wrapper. Gets the `{id}-frame` ID, and its name from `Root`'s `label` or the title.    |
| `Toolbar`         | `<header>`  | Wrapper for controls.                                                                        |
| `Title`           | `<span>`    | The active view's title, or its children. Gets the `{id}-title` ID.                          |
| `PreviousTrigger` | `<button>`  | Moves back one step of the active view. Disabled when no view is active.                     |
| `NextTrigger`     | `<button>`  | Moves forward one step of the active view. Disabled when no view is active.                  |
| `TodayTrigger`    | `<button>`  | Moves to today in the calendar's time zone, from `now`, `clock`, or the system clock.        |
| `ViewSwitcher`    | `<select>`  | One option per view. Requires `getViewLabel(name)`.                                          |
| `Viewport`        | `<div>`     | Wrapper for the view. Gets the `{id}-viewport` ID.                                           |
| `ActiveView`      | view output | Renders the active view, or `fallback` if it isn't registered.                               |
| `Event`           | your output | Looks up one event by `eventId` and calls `children` with it<Solid>, as an accessor</Solid>. |
| `Announcer`       | `<div>`     | A hidden live region that speaks moves, resizes, and creates. Requires `messages`.           |

- The buttons default to `type="button"` and set `aria-controls` to the viewport. Give each one
  text or an `aria-label`.
- Your `onClick` or `onChange` runs first. Call `event.preventDefault()` in it to skip the built-in
  action.
- `Frame`, `Title`, and `Viewport` don't accept `id`. Set `id` on `Root` instead, so the IDs and
  `aria-controls` always match.
- The parts are [ui-sdk](https://ui-sdk.dev) components, which is how an
  [agent bridge](/docs/agents/connect) finds a calendar. A calendar is listed for agents only when
  it renders `Frame`. Events and cells stay elements your views render.

`Event` passes your record and its normalized form:

```tsx
    <p>

  )}
</Calendar.Event>
```

</React>

## Hooks

The hooks on your calendar work anywhere inside its `Root`. Using them, or any component above,
outside `Root` throws `calendar-hook-outside-root`.

<Solid>

A hook that reads a value returns an accessor, so call it where you use the value: `state().view`,
`range()`. `useCalendarActions()` returns a plain object, and `useCalendar()`'s `state` and `meta`
are getters: read them in JSX, a memo or an effect, and don't destructure them.

</Solid>

| Hook                                          | Returns                                                                                                                |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `useCalendar()`                               | `{ state, actions, meta }`                                                                                             |
| `useCalendarState()`                          | The six [state](/docs/concepts/state) values                                                                           |
| `useCalendarActions()`                        | The actions below. The object never changes.                                                                           |
| `useCalendarMeta()`                           | The [meta](#meta) object                                                                                               |
| `useCalendarSelector(selector, opts?)`        | `selector(state)`. <React>Re-renders</React><Solid>Updates</Solid> only when it changes.                               |
| `useCalendarPendingChanges(selector?, opts?)` | The changes still on their way, or `selector(changes)`. See [pending changes](/docs/interactions#across-the-calendar). |
| `useVisibleRange()`                           | The active view's visible dates, or `null`                                                                             |
| `useViewProjection()`                         | The active view and its projection, or `null`                                                                          |

`useCalendarSelector` and `useCalendarPendingChanges` compare results with `Object.is`. Pass
`{ isEqual }` to compare another way. The selector can be an inline function.

`useCalendarHistory(history, { messages? })` is exported on its own too. It binds an event history
to the nearest `Root`, with `undo`, `redo`, `canUndo` and `canRedo`, and
`useCalendarHistoryShortcuts(history, options)` adds its keys, with the options `scope`, `undo`,
`redo` and `disabled`<Solid>, as an object or an accessor of one</Solid>; see
[Undo and redo](/docs/undo-redo).

`useCalendarPointer(options)` is exported on its own too. It returns the ref that turns drags in
a custom view into proposals; see the [pointer layer](/docs/api/changes#pointer-layer).<React> It's in
`@moltenship/calendar-react` from 2.0 on, and was in `@moltenship/calendar-dnd` in 1.x.</React>

`Announcer`'s messages, and the keyboard hooks for your own views (`useCalendarKeyboard`,
`useRovingFocus`, `useCalendarInteraction`, `useCalendarAnnouncer`), are covered in
[Accessibility](/docs/accessibility#announcements).

`useNow({ intervalMs })` is exported on its own, not from your calendar. It returns the current
instant from the nearest `Root`'s `now` or `clock`, or the system clock, and samples it every
`intervalMs` (one minute by default). It returns `null` during server rendering and hydration unless
`Root` has `now`.

`useAnchorDateRequests(listener)` calls `listener(date, range)` with every date the calendar is
asked to show: from Previous, Next, Today, keys paging past the view, or `setAnchorDate`. That
includes a date that is already the anchor. `range` holds the dates the active view shows for
`date`, so a week view can tell Today inside its week from a date that moves it. A view whose
scroll position can run ahead of the anchor uses it to show its range again when Today asks for
it. The [scrolling views](/docs/views/scrolling) do this.

### Actions

| Action                                  | Effect                                                                                                                                                                                                                                            |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `setView(name, options?)`               | Changes the view. Every setter and navigation action takes `{ event?, reason?, source? }` last, for the [change handler](/docs/concepts/state#what-a-handler-hears)                                                                               |
| `setAnchorDate(date)`                   | Changes the date                                                                                                                                                                                                                                  |
| `setTimeZone(zone)`                     | Changes the time zone                                                                                                                                                                                                                             |
| `setSelection(value)`                   | Changes the selection (`null` clears it)                                                                                                                                                                                                          |
| `setFocus(value)`                       | Changes the focus (`null` clears it)                                                                                                                                                                                                              |
| `setExpandedResourceIds(ids)`           | Changes the expanded resources                                                                                                                                                                                                                    |
| `navigatePrevious()`, `navigateNext()`  | Moves by one step of the active view                                                                                                                                                                                                              |
| `navigateToday()`                       | Moves to today in the calendar's time zone                                                                                                                                                                                                        |
| `proposeEventChange(proposal, detail?)` | Proposes a change to an event and resolves with the outcome. `detail.input` names the input for policies, `onEventChange` and `onEventChangeResult`, `"api"` by default. See [Interactions](/docs/interactions#changing-events-from-your-own-ui). |
| `checkEventChange(proposal, detail?)`   | Runs the policies on a proposal without showing or saving it. Returns `{ status: "accepted", change }` or `{ status: "rejected", change, reason }`, or `null` for an unknown event or an async policy.                                            |

Setting the current value again (the same date, view, time zone or resource IDs, or the same
`selection` or `focus` object) doesn't change state or call its handler, unless the value is
controlled and you haven't applied a change the calendar asked for (see
[State](/docs/concepts/state)). `useAnchorDateRequests` still hears a request for the current anchor
date. Calling two actions in a row builds on the
first, so `navigateNext(); navigateNext()` moves two steps, even for controlled values.

## Diagnostics

Problems that don't stop rendering are collected in `meta.diagnostics` and passed to
`onDiagnosticsChange`. Time doesn't log them.

| `code`                        | `severity` | Cause                                                                                                                                         |
| ----------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `unregistered-active-view`    | error      | The `view` state names a view that isn't registered.                                                                                          |
| `invalid-event`               | error      | A record was skipped. `issue` has the details ([issue codes](/docs/api/events#invalid-records)).                                              |
| `invalid-annotation`          | error      | An annotation was skipped. `issue` has its `code`, `index`, and the `annotation`.                                                             |
| `invalid-availability`        | error      | A working-hours rule, exception, or time zone was left out. `issue` has the `code`, the `value`, and the `resourceId` when it's a resource's. |
| `invalid-secondary-time-zone` | error      | An entry of `secondaryTimeZones` was left out. `issue` has the `value`, and its `index` in a list.                                            |

## Server rendering

`Root`, the parts and every hook render on the server with `@solidjs/web`'s `renderToString`, and
hydrate without a mismatch. On the server the calendar doesn't read the clock, the host time zone
or `window`. Without `now`, `useNow` gives `null` on the server and while hydrating, and the tab
stop is the view's entry, which is today only when `now` is set. A store with `getServerSnapshot`
renders that snapshot on the server and while hydrating. The keyboard and pointer refs attach
nothing until the page hydrates.

</Solid>
