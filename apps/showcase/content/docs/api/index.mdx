title: Overview

In a React app, import from `@moltenship/calendar`. It includes the React components and hooks,
the event engine, the Temporal helpers, and the pointer interactions, so one import line covers the
calendar:

```ts
import { createCalendar, defineCalendarView, plainDateInterval } from "@moltenship/calendar";
```

In a Solid app, the factory, the parts and the hooks come from `@moltenship/calendar-solid`, and
the engine from `@moltenship/calendar-core`. The pages under "Engine and state" in the sidebar
name `@moltenship/calendar` as the import. In Solid, events, changes and policies come from
`@moltenship/calendar-core`. The Temporal helpers come from `@moltenship/calendar-temporal`, which
you install beside it as `@moltenship/calendar-temporal@next`. The store comes from
`@moltenship/calendar-solid`. The pointer layer, `@moltenship/calendar-dnd`, imports no framework,
but the Solid package doesn't bind it yet.

The iCalendar parser, `@moltenship/ics`, stands alone. `@moltenship/calendar` doesn't re-export it,
so install it and import it by its own name. It doesn't need the calendar either.

Recurring events come from `@moltenship/calendar-recurrence`, which `@moltenship/calendar` doesn't
re-export either. It turns series into occurrences that the calendar shows as ordinary events.

`@moltenship/calendar-dnd-kit` connects the calendar to dnd-kit, for apps that drag their own items
into it. It's optional and not re-exported, so the calendar's install carries no dnd-kit.

Tests use `@moltenship/calendar-testing`, a development dependency: see [Testing](/docs/testing).

The agent bridge isn't the calendar's: `createAgent`, `agentTools` and `registerTools` come from
`@ui-sdk/react/agent`, which your app imports itself. See [Agents in your app](/docs/agents).

## Packages

| Package                           | Contents                                                                                                                              | Dependencies                                                                                                                     |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `@moltenship/calendar`            | Re-exports `calendar-react`, `-core`, `-temporal` and `-dnd`. Since 2.0 it ships these docs as Markdown and a skill for coding agents | Those four; React 19, `@ui-sdk/core`, `@ui-sdk/react` (peers)                                                                    |
| `@moltenship/calendar-react`      | `createCalendar`, `defineCalendarView`, components, hooks, store                                                                      | `calendar-primitives`, `calendar-dnd`, `calendar-core`, `calendar-temporal`; React 19, `@ui-sdk/core`, `@ui-sdk/react` (peers)   |
| `@moltenship/calendar-primitives` | The calendar's state, actions and runtime, agent actions included, with no framework. Not re-exported.                                | `calendar-core`, `calendar-temporal`; `@ui-sdk/core` (peer)                                                                      |
| `@moltenship/calendar-solid`      | `createCalendar`, `defineCalendarView`, parts and read hooks for SolidJS 2. A preview. Not re-exported.                               | `calendar-primitives`, `calendar-core`, `calendar-temporal`; `solid-js`, `@solidjs/web`, `@ui-sdk/core`, `@ui-sdk/solid` (peers) |
| `@moltenship/calendar-core`       | Adapters, validation, snapshots, queries, changes and policies, view strategies, availability. No React.                              | `calendar-temporal`, `@flatten-js/interval-tree`                                                                                 |
| `@moltenship/calendar-temporal`   | Ranges, grids, rounding, zoned days, DST                                                                                              | None                                                                                                                             |
| `@moltenship/calendar-dnd`        | Pointer drag, resize, and create for views, with no framework                                                                         | `calendar-core`, `calendar-temporal`                                                                                             |
| `@moltenship/ics`                 | iCalendar parsing into Temporal values. Not re-exported.                                                                              | None                                                                                                                             |
| `@moltenship/calendar-recurrence` | Series expansion, occurrence IDs, series edits. Not re-exported.                                                                      | `calendar-core`, `calendar-temporal`, `ics`                                                                                      |
| `@moltenship/calendar-dnd-kit`    | dnd-kit items dragged in, events dragged out. Not re-exported.                                                                        | `calendar-dnd`, `calendar-core`; React 19, dnd-kit 0.5 (peers)                                                                   |
| `@moltenship/calendar-testing`    | A test harness for your calendar: fixed clock, builders, render and hydration. See [Testing](/docs/testing).                          | `calendar`, `calendar-recurrence`; React and React DOM 19, `@ui-sdk/core`, `@ui-sdk/react` (peers)                               |

Every package is ESM only. Import from the package name: paths inside a package aren't part of the
API.
