Import from `@moltenship/calendar` in a React app. It includes everything in
`@moltenship/calendar-react` and `@moltenship/calendar-core`, so one import line covers components,
hooks, adapters, and snapshots:

```ts
import { createCalendar, defineCalendarView, defineEventAdapter } from "@moltenship/calendar";
```

`@moltenship/calendar-temporal` is separate. Install it when you write views that need date ranges
or time zone helpers.

## Packages

| Package                         | Contents                                                | Dependencies                                     |
| ------------------------------- | ------------------------------------------------------- | ------------------------------------------------ |
| `@moltenship/calendar`          | Re-exports `calendar-react` and `calendar-core`         | Both of those; React 19 (peer)                   |
| `@moltenship/calendar-react`    | `createCalendar`, components, hooks, views, state store | `calendar-core`, `jotai`; React 19 (peer)        |
| `@moltenship/calendar-core`     | Adapters, validation, snapshots, queries. No React.     | `calendar-temporal`, `@flatten-js/interval-tree` |
| `@moltenship/calendar-temporal` | Ranges, grids, rounding, zoned days, DST                | None                                             |

Every package is ESM only. Import from the package name: paths inside a package aren't part of the
API.
