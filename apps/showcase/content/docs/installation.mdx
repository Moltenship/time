## Requirements

- **React 19.** React is a peer dependency.
- **A JavaScript runtime with `Temporal`.** Node.js 26 and later include it. Browser support is
  still rolling out, so check the
  [MDN compatibility table](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal#browser_compatibility)
  for the browsers you support and add a polyfill if needed (see below).
- **TypeScript 6 or later** with `"lib": ["DOM", "DOM.Iterable", "ESNext"]`. `ESNext` has the
  `Temporal` types.

`@moltenship/calendar` is the only package most apps import. It includes the React components, the
event engine, the Temporal helpers, and the pointer interactions. Recurring events add
`@moltenship/calendar-recurrence`, reading ICS feeds `@moltenship/ics`, and dragging your own
dnd-kit items into the calendar `@moltenship/calendar-dnd-kit`. See [How it works](/docs/concepts/how-it-works) for what's inside.

## Temporal

Time uses the global `Temporal` object and never bundles a polyfill. In a runtime without
`Temporal`, load one before any code that imports the calendar. This entry file loads
[`temporal-polyfill`](https://www.npmjs.com/package/temporal-polyfill) only where it's missing,
then loads the app:

```tsx title="main.tsx"
if (!("Temporal" in globalThis)) await import("temporal-polyfill/global");

// Import the app afterwards, so no module runs before Temporal exists.
const { App } = await import("./app");
```

Any polyfill that defines `globalThis.Temporal` works.

## TypeScript

Make sure your `tsconfig.json` includes the `ESNext` library so `Temporal` is typed:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "lib": ["DOM", "DOM.Iterable", "ESNext"]
  }
}
```

## UI source (optional)

The packages render plain, unstyled elements. The styled views, toolbar and theme are source files
that you add to your app and then own, the way shadcn/ui works. They install with the shadcn CLI
from this site's registry. There's no other installer.

<Steps>
<Step>

Set up [shadcn/ui](https://ui.shadcn.com/docs/installation) with Tailwind CSS 4 if your app
doesn't use it yet. The files need shadcn's default primitives, built on
[Base UI](https://base-ui.com), which `init` sets up:

```bash
npx shadcn@latest init
```

If your app already uses shadcn/ui, check that `style` in `components.json` starts with `base-`,
such as `base-nova`. `shadcn add` installs components in your app's existing style, and the
calendar's files don't compile against primitives from other styles.

</Step>
<Step>

Add the calendar. `calendar-full` installs every view, the theme and the parts they share:

```bash
npx shadcn@latest add https://time.molten.sh/r/calendar-full.json
```

Or add only the views you use. Each one brings what it builds on: the theme, the shared
`calendar` parts, the shadcn components it uses, and npm packages such as `@moltenship/calendar`.

| Item                       | What it adds                                                                 |
| -------------------------- | ---------------------------------------------------------------------------- |
| `calendar-full`            | Every item below                                                             |
| `calendar-theme`           | The calendar's tokens and event colors, added to your global CSS             |
| `calendar`                 | `CalendarToolbar`, `ViewSwitcher`, `EventChip`, `MiniMonth` and shared parts |
| `time-grid-view`           | The [week and day](/docs/views/week-and-day) views                           |
| `month-view`               | The [month](/docs/views/month) view                                          |
| `list-view`                | The [agenda](/docs/views/agenda) view                                        |
| `year-view`                | The [year](/docs/views/year) view                                            |
| `scrolling-time-grid-view` | The [scrolling](/docs/views/scrolling) week and day views                    |
| `scrolling-month-view`     | The scrolling month view                                                     |
| `scrolling-list-view`      | The scrolling agenda                                                         |
| `resource-columns-view`    | The [resource columns](/docs/views/resource-columns) view                    |
| `resource-timeline-view`   | The [resource timeline](/docs/views/resource-timeline) views                 |
| `recurrence-scope-dialog`  | The [recurrence scope dialog](/docs/guides/recurring-events)                 |
| `calendar-history-toast`   | The [undo toast](/docs/undo-redo#undo-toast)                                 |

Each item's address is `https://time.molten.sh/r/<item>.json`:

```bash
npx shadcn@latest add https://time.molten.sh/r/month-view.json
```

The files land in `calendar/` under the `components` alias in your `components.json`, such as
`components/calendar/month-view/month-view.tsx`, and their imports follow your aliases. Each item
asks for the `@moltenship/calendar` versions it was built for, and `shadcn add` installs a
matching one.

To add items by name, add the registry to `components.json` once:

```json title="components.json"
{
  "registries": {
    "@moltenship": "https://time.molten.sh/r/{name}.json"
  }
}
```

Then `npx shadcn@latest add @moltenship/month-view` works too.

</Step>
<Step>

The toolbar's buttons use shadcn's tooltip, so wrap your app in `TooltipProvider` from
`@/components/ui/tooltip` once, as `shadcn add` reminds you and shadcn's
[tooltip instructions](https://ui.shadcn.com/docs/components/tooltip) describe.

</Step>
</Steps>

The theme's tokens and rules go into your global CSS inside `@layer base`, so your own rules win
over them. Each `shadcn add` writes that block again, so change tokens in your own rules instead,
as [Theming](/docs/theming#changing-tokens) shows. Run `shadcn add` again to update the files: it
asks before it replaces a file you already have, and `--overwrite` replaces them all, with any
changes you made.

## Run from source

To work on Time, or to try changes that aren't released yet, run it and this documentation site
from the repository. You need Node.js 26 and the [Vite+ CLI](https://viteplus.dev/guide/) (`vp`).

```bash
git clone https://github.com/Moltenship/time.git
cd time
vp install
vp run dev
```

`vp run dev` starts this site locally. The examples on these pages are real files in
`apps/showcase/content/examples`, type-checked against the current packages.

Next, build a calendar in the [Quick start](/docs/quick-start).
