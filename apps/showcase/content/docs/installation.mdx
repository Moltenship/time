## Requirements

- **React 19.** React is a peer dependency.
- **A JavaScript runtime with `Temporal`.** Node.js 26 and later include it. Browser support is
  still rolling out, so check the
  [MDN compatibility table](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal#browser_compatibility)
  for the browsers you support and add a polyfill if needed (see below).
- **TypeScript 6 or later** with `"lib": ["ESNext"]`, which includes the `Temporal` types.

`@moltenship/calendar` is the only package you import. It includes the React components, the event
engine, the Temporal helpers, and the pointer interactions. See [How it works](/docs/concepts/how-it-works) for what's inside.

## Temporal

Time uses the global `Temporal` object and never bundles a polyfill. In a runtime without
`Temporal`, load one before any code that imports the calendar. This entry file loads
[`temporal-polyfill`](https://www.npmjs.com/package/temporal-polyfill) only where it's missing,
then loads the app:

```tsx title="main.tsx"
if (!("Temporal" in globalThis)) await import("temporal-polyfill/global");

// Import the app afterwards, so no module runs before Temporal exists.
const { App } = await import("./app");
```

Any polyfill that defines `globalThis.Temporal` works.

## TypeScript

Make sure your `tsconfig.json` includes the `ESNext` library so `Temporal` is typed:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "lib": ["DOM", "DOM.Iterable", "ESNext"]
  }
}
```

## UI source (optional)

The packages render plain, unstyled elements. Styled parts built on them live in the repository's
[`registry`](https://github.com/Moltenship/time/tree/main/registry) folder, as source you copy into
your app and then own, the same way shadcn/ui works:

- `registry/calendar-theme`: `calendar-theme.css` (calendar tokens and event colors) and
  `event-colors.ts` (the color names). See [Theming](/docs/theming).
- `registry/calendar`: `CalendarToolbar`, `ViewSwitcher`, `EventChip`, and `MiniMonth`.
- `registry/time-grid-view`, `registry/month-view`, and `registry/list-view`: the
  [week and day](/docs/views/week-and-day), [month](/docs/views/month), and
  [agenda](/docs/views/agenda) views.

<Callout type="warn" title="Moving to Base UI">
  shadcn/ui now sets up Base UI primitives by default, and the registry files are being updated to
  match. Until that update lands, the copied toolbar and month view don't compile against Base UI
  primitives. To see the views working in the meantime, open the [live
  demo](https://moltenship-time-demo.vercel.app).
</Callout>

There's no `shadcn add` command for these files yet, so copy them by hand:

<Steps>
<Step>

Set up [shadcn/ui](https://ui.shadcn.com/docs/installation) with Tailwind CSS 4 if your app
doesn't use it yet:

```bash
npx shadcn@latest init
```

Then add the primitives the files import, and the icons if your app doesn't have them yet:

```bash
npx shadcn@latest add button popover select tooltip
pnpm add lucide-react
```

shadcn's tooltip also needs a `TooltipProvider` at the root of your app, as its
[installation notes](https://ui.shadcn.com/docs/components/tooltip) describe.

</Step>
<Step>

Copy the files into your app. Each folder's `registry-item.json` lists a suggested `target` path,
such as `components/calendar/calendar-toolbar.tsx` and `styles/calendar-theme.css`.

</Step>
<Step>

The copied files import each other through `@registry/…`. Change those imports to your own paths.
In a default shadcn setup they map like this. The last row is there because `@moltenship/calendar`
already includes the Temporal helpers:

| Import in the copied file               | Change it to                         |
| --------------------------------------- | ------------------------------------ |
| `@registry/ui/button` (and other `ui/`) | `@/components/ui/button`             |
| `@registry/lib/utils`                   | `@/lib/utils`                        |
| `@registry/calendar/…`                  | `@/components/calendar/…`            |
| `@registry/calendar-theme/event-colors` | `@/components/calendar/event-colors` |
| `@moltenship/calendar-temporal`         | `@moltenship/calendar`               |

</Step>
<Step>

Import the theme in your global CSS, after the Tailwind and shadcn imports that are already there.
The path is relative to the CSS file:

```css title="index.css"
@import "tailwindcss";
@import "tw-animate-css";
@import "shadcn/tailwind.css";
@import "./styles/calendar-theme.css";
```

A shadcn app already defines the `dark` variant. If yours doesn't, add
`@custom-variant dark (&:is(.dark *));` below the imports.

</Step>
</Steps>

## Run from source

Until the first release, you can run Time and this documentation site from the repository. You need
Node.js 26 and the [Vite+ CLI](https://viteplus.dev/guide/) (`vp`).

```bash
git clone https://github.com/Moltenship/time.git
cd time
vp install
vp run dev
```

`vp run dev` starts this site locally. The examples on these pages are real files in
`apps/showcase/content/examples`, type-checked against the current packages.
