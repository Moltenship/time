## Requirements

<React>

- **React 19.** React and React DOM are peer dependencies.
- **ui-sdk.** `@ui-sdk/core` and `@ui-sdk/react` are peer dependencies since 2.0. The calendar's
  parts are [ui-sdk](https://ui-sdk.dev) components, which is how an [agent](/docs/agents) reaches
  them. ui-sdk is in beta, and the calendar takes `0.1.0-beta.16` and the betas after it.

</React>

<Solid>

- **SolidJS 2.0.** `solid-js` and `@solidjs/web` are peer dependencies.
- **ui-sdk.** `@ui-sdk/core` and `@ui-sdk/solid` are peer dependencies. The calendar's parts are
  [ui-sdk](https://ui-sdk.dev) components, which is how an
  [agent](/docs/agents) reaches them. ui-sdk is in beta, and the calendar takes
  `0.1.0-beta.16` and the betas after it.

</Solid>

- **A JavaScript runtime with `Temporal`.** Node.js 26 and later include it. Browser support is
  still rolling out, so check the
  [MDN compatibility table](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal#browser_compatibility)
  for the browsers you support and add a polyfill if needed (see below).
- **TypeScript 6 or later** with `"lib": ["DOM", "DOM.Iterable", "ESNext"]`. `ESNext` has the
  `Temporal` types.

`@moltenship/calendar` is the only calendar package most React apps import. It includes the React
components, the event engine, the Temporal helpers, and the pointer interactions. Recurring events
add [`@moltenship/calendar-recurrence`](/docs/recurrence), reading ICS feeds
[`@moltenship/ics`](/docs/ics), and dragging your own dnd-kit items into the calendar
`@moltenship/calendar-dnd-kit`. See [How it works](/docs/concepts/how-it-works) for what's inside.

You import ui-sdk yourself in one case: to create the [agent bridge](/docs/agents/connect), from
`@ui-sdk/react/agent`. Keep one copy of `@ui-sdk/core` in your app. The calendar and the bridge
find each other through it, and with two copies an agent sees no calendar. Your package manager
keeps one as long as every `@ui-sdk/*` package is on the same version.

`@moltenship/calendar-solid` is the only calendar package most Solid apps import. It has the parts
and the hooks, and it re-exports the event engine and the [Temporal helpers](/docs/temporal), so

## Build setup

The integration is plain TypeScript, and `@ui-sdk/solid` ships JSX for your app's Solid compiler.
With Vite, use Solid's plugin:

<include meta='title="vite.config.ts"'>../examples/solid/vite.config.ts#config</include>

```json title="tsconfig.json"
{
  "compilerOptions": {
    "jsx": "preserve",
    "jsxImportSource": "@solidjs/web",
    "lib": ["ESNext", "DOM", "DOM.Iterable"]
  }
}
```

If the page fails with `React is not defined` from a file in `@ui-sdk/solid`, the plugin didn't
compile that package as Solid. Check that `@ui-sdk/solid` is in your app's own `dependencies`,
where the install command puts it.

</Solid>

## Temporal

Time uses the global `Temporal` object and never bundles a polyfill. In a runtime without
`Temporal`, load one before any code that imports the calendar. This entry file loads
[`temporal-polyfill`](https://www.npmjs.com/package/temporal-polyfill) only where it's missing,
then loads the app:

```tsx title="main.tsx"
if (!("Temporal" in globalThis)) await import("temporal-polyfill/global");

// Import the app afterwards, so no module runs before Temporal exists.
const { App } = await import("./app");
```

Any polyfill that defines `globalThis.Temporal` works.

## UI source (optional)

The packages render plain, unstyled elements. The styled views, toolbar and theme are React source
files that you add to your app and then own, the way shadcn/ui works. They install with the shadcn
CLI from this site's registry. There's no other installer. An app that brings its own UI skips
this section, as [Build your own UI](/docs/customization#level-4-build-your-own-ui) describes.

<Steps>
<Step>

Set up [shadcn/ui](https://ui.shadcn.com/docs/installation) with Tailwind CSS 4 if your app
doesn't use it yet. `shadcn add` needs its `components.json`, and the calendar's files use its
tokens, such as `--background` and `--primary`:

```bash
npx shadcn@latest init
```

Any style works: the calendar brings its own controls and uses none of your app's components. An
app with a `components.json` but without shadcn's tokens gets shadcn's neutral ones from
`base-tokens`:

```bash
npx shadcn@latest add https://time.molten.sh/r/base-tokens.json
```

</Step>
<Step>

Add the calendar. `calendar-full` installs every view, the theme and the parts they share:

```bash
npx shadcn@latest add https://time.molten.sh/r/calendar-full.json
```

Or add only the views you use. Each one brings what it builds on: the theme, the shared
`calendar` parts, the calendar's controls, and npm packages such as `@moltenship/calendar`.

| Item                       | What it adds                                                                 |
| -------------------------- | ---------------------------------------------------------------------------- |
| `calendar-full`            | Every item below but `base-tokens`                                           |
| `calendar-theme`           | The calendar's tokens and event colors, added to your global CSS             |
| `calendar-ui`              | The calendar's controls and popups, built on ui-sdk                          |
| `calendar`                 | `CalendarToolbar`, `ViewSwitcher`, `EventChip`, `MiniMonth` and shared parts |
| `time-grid-view`           | The [week and day](/docs/views/week-and-day) views                           |
| `month-view`               | The [month](/docs/views/month) view                                          |
| `list-view`                | The [agenda](/docs/views/agenda) view                                        |
| `year-view`                | The [year](/docs/views/year) view                                            |
| `scrolling-time-grid-view` | The [scrolling](/docs/views/scrolling) week and day views                    |
| `scrolling-month-view`     | The scrolling month view                                                     |
| `scrolling-list-view`      | The scrolling agenda                                                         |
| `resource-columns-view`    | The [resource columns](/docs/views/resource-columns) view                    |
| `resource-timeline-view`   | The [resource timeline](/docs/views/resource-timeline) views                 |
| `recurrence-scope-dialog`  | The [recurrence scope dialog](/docs/recurrence/calendar)                     |
| `calendar-history-toast`   | The [undo toast](/docs/undo-redo#undo-toast)                                 |
| `base-tokens`              | shadcn/ui's neutral tokens, for an app without them                          |

Each item's address is `https://time.molten.sh/r/<item>.json`:

```bash
npx shadcn@latest add https://time.molten.sh/r/month-view.json
```

The files land in `calendar/` under the `components` alias in your `components.json`, such as
`components/calendar/month-view/month-view.tsx`, and their imports follow your aliases. Each item
asks for the `@moltenship/calendar` versions it was built for, and `shadcn add` installs a
matching one. `calendar-ui` lists `@ui-sdk/core` and `@ui-sdk/react`, so `shadcn add` adds them if
your app doesn't have them yet. Keep them on the version the calendar uses, as above.

To add items by name, add the registry to `components.json` once:

```json title="components.json"
{
  "registries": {
    "@moltenship": "https://time.molten.sh/r/{name}.json"
  }
}
```

Then `npx shadcn@latest add @moltenship/month-view` works too.

</Step>
<Step>

The calendar's controls come from `calendar-ui`, not from your app's `components/ui`: its
buttons, badges, tooltips, selects, popovers, dialogs and toasts. They're a default: to use your
own, see
[Use your own controls](/docs/theming#use-your-own-controls). ui-sdk
adds a little CSS of its own to the page, in a layer named `ui-sdk`. Name that layer before
Tailwind in your global CSS, so your styles and Tailwind's win over it:

```css title="globals.css"
@layer ui-sdk;
@import "tailwindcss";
```

The calendar's popups, such as the view select's list, its tooltips, popovers and dialogs, open
in the browser's top layer, through the Popover API: Chrome and Edge 114, Safari 17 and Firefox 125 or later. In an older browser they
render at the end of the page instead, and a server-rendered page doesn't hydrate them cleanly.
The toolbar's tooltips open after 400 ms; change `tooltipDefaults` in
`components/calendar/ui/tooltip.styles.ts`, or pass `delay` to a `Tooltip`.

</Step>
</Steps>

For an app on StyleX rather than Tailwind, every item has a `stylex-` version; see
[StyleX](/docs/stylex).

The theme's tokens and rules go into your global CSS inside `@layer base`, so your own rules win
over them. Each `shadcn add` writes that block again, so change tokens in your own rules instead,
as [Theming](/docs/theming#changing-tokens) shows. Run `shadcn add` again to update the files: it
asks before it replaces a file you already have, and `--overwrite` replaces them all, with any
changes you made.

</React>

## UI source (optional)

The package renders plain, unstyled elements. The registry has styled Solid views, the
[week and day](/docs/views/week-and-day), the [month](/docs/views/month), the [year](/docs/views/year) and the [agenda](/docs/views/agenda), with the [toolbar and mini month](/docs/views/toolbar), the
[recurring-event dialog](/docs/recurrence/calendar), the [undo toast](/docs/undo-redo#undo-toast)
and the [controls](/docs/views/controls) they're built from, as source files that you add to your app and
then own, the way shadcn/ui works. They install with the shadcn CLI from this site's Solid registry,
at `https://time.molten.sh/r/solid`. The other views aren't in it yet, so you write those: the
[Quick start](/docs/quick-start) writes the first one, and [Custom views](/docs/views/custom-views)
covers the rest. [What's coming](/docs/frameworks#whats-coming) has the plan.

| Item                      | What it adds                                                                                                                                   |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `time-grid-view`          | The [week and day](/docs/views/week-and-day)                                                                                                   |
| `month-view`              | The [month](/docs/views/month)                                                                                                                 |
| `year-view`               | The [year](/docs/views/year)                                                                                                                   |
| `list-view`               | The [agenda](/docs/views/agenda)                                                                                                               |
| `recurrence-scope-dialog` | The [recurring-event dialog](/docs/recurrence/calendar), which asks which events of a series a change applies to                               |
| `calendar-history-toast`  | The [undo toast](/docs/undo-redo#undo-toast), with the undo and redo keys                                                                      |
| `calendar`                | The [toolbar, view switcher and mini month](/docs/views/toolbar), and the event chip, names and keys the views share                           |
| `calendar-ui`             | The [controls](/docs/views/controls) the views are built from, on ui-sdk: button, badge, tooltip, select, popover, dialog, toast and the icons |
| `calendar-theme`          | The calendar's color tokens and its event colors, in `event-colors.ts`                                                                         |
| `base-tokens`             | shadcn/ui's neutral tokens for light and dark, for an app without them                                                                         |

`time-grid-view`, `month-view`, `year-view` and `list-view` bring `calendar`, `calendar-ui` and `calendar-theme` with them. An app with its own shadcn/ui-style
theme, which defines `--background`, `--border`, `--primary` and the rest, skips `base-tokens`.

<Steps>
<Step>

### Set up Tailwind CSS 4

The files style themselves with Tailwind classes, so the app needs Tailwind CSS 4 and its
preflight. With Vite, add `@tailwindcss/vite` to the plugins in the `vite.config.ts` above, after
Solid's.

Import Tailwind in your global stylesheet, below an `@layer ui-sdk;` that puts your styles after
the CSS ui-sdk adds to the page, and make Tailwind's `dark:` variant follow a `.dark` ancestor, as
the theme does:

<include meta='title="src/app.css"'>../examples/solid/app.css</include>

The files import each other through the `@/` alias. Map it in `tsconfig.json`, beside the
settings above:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "paths": { "@/*": ["./src/*"] }
  }
}
```

With Vite, also set `resolve: { tsconfigPaths: true }` in `vite.config.ts`, so the dev server
reads that alias.

</Step>
<Step>

### Point the shadcn CLI at the Solid registry

The CLI has no Solid template to `init` from, so write `components.json` at the app's root
yourself. `registries` names the Solid registry, so `@moltenship/<item>` installs the Solid items,
and `tailwind.css` names the stylesheet the theme's tokens go into:

<include meta='title="components.json"'>../examples/solid/components.json</include>

</Step>
<Step>

### Add the items

```bash
npx shadcn@latest add @moltenship/base-tokens @moltenship/list-view
```

Without `registries` in `components.json`, give the item's full address instead:

```bash
npx shadcn@latest add https://time.molten.sh/r/solid/list-view.json
```

```txt
├── resource-status.tsx

├── …                        their styles and logic
├── ui                       calendar-ui

│   ├── icons.tsx
```

a view's classes, its words and its keys are each in one file. `shadcn add`
adds the npm packages the files import, such as `@tanstack/virtual-core`, if your app doesn't have
them yet. Each item names the range of `@moltenship/calendar-solid` it's built for, so the CLI
installs a version the files compile against.

Add the agenda to your calendar, and render it in `Calendar.ActiveView`:

The theme switches when an ancestor of the calendar has the `dark` class, as shadcn/ui does. Toggle
it on `<html>` from your app's theme setting; the `@custom-variant` line in `src/app.css` makes the
files' `dark:` classes follow the same class. The theme's tokens go into `src/app.css` inside
`@layer base`, so your own rules win over them: change a token in a rule of your own, as
[Theming](/docs/theming#changing-tokens) shows.

The files are copies you own: edit them as you would any component. A fix in the registry reaches
your app when you add the item again. The command writes the files your app doesn't have, skips
the ones that match, and asks before it replaces one that differs. `--dry-run` lists what it would
do, and `--diff` with a path from that list prints the difference, writing nothing:

```bash
npx shadcn@latest add @moltenship/list-view --dry-run
npx shadcn@latest add @moltenship/list-view --diff src/components/calendar/list-view/agenda-view.tsx
```

## Run from source

To work on Time, or to try changes that aren't released yet, run it and this documentation site
from the repository. You need Node.js 26 and the [Vite+ CLI](https://viteplus.dev/guide/) (`vp`).

```bash
git clone https://github.com/Moltenship/time.git
cd time
vp install
vp run dev
```

`vp run dev` starts this site locally. The examples on these pages are real files, type-checked
against the current packages. They are in <React>`apps/showcase/content/examples`</React><Solid>`apps/showcase/content/examples/solid`</Solid>.

Next, build a calendar in the [Quick start](/docs/quick-start).
