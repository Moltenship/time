Time's behaviour lives in packages that import no UI framework. An integration package renders it
in one framework. There are two integrations. React is complete, and SolidJS 2 is a preview.

<Callout type="warn" title="Solid is a preview">
  `@moltenship/calendar-solid` has the typed factory, `Root`, the structural parts and the read
  hooks. It has no ready-made views, no keyboard navigation, no dragging, no gesture previews and no
  undo bindings yet. Its API can change in any release before 2.0.0. The code samples on the other
  pages are React.
</Callout>

## The layers

```text
views         React source from the registry, or components you write
integration   @moltenship/calendar (React)       @moltenship/calendar-solid (Solid)
calendar      @moltenship/calendar-primitives    state, actions, what an agent can call
engine        @moltenship/calendar-core          events, time zones, layout, changes, policies
              @moltenship/calendar-temporal
```

The engine and the calendar layer import neither React nor Solid. Each integration is a thin
package over them. It renders the parts and binds state to its framework's reactivity. The React
and Solid integrations don't import each other.

## What is the same

These work the same in both frameworks, because they run below the integration:

| Topic             | What both frameworks share                                                                                 | Read                                              |
| ----------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Events            | `defineEventAdapter`, validation, snapshots and queries                                                    | [Events and adapters](/docs/concepts/events)      |
| Time              | `Temporal` values, timed, all-day and floating events, time zones and daylight saving time                 | [Time and time zones](/docs/concepts/time)        |
| State             | The six state values, controlled and uncontrolled props, change handlers, and `createCalendarStore`        | [State](/docs/concepts/state)                     |
| Recurrence        | `@moltenship/calendar-recurrence` turns series into ordinary events before the calendar sees them          | [Recurring events](/docs/concepts/recurrence)     |
| Changes           | Proposals, `onEventChange`, `onEventChangeResult`, policies and pending changes                            | [Interactions](/docs/interactions#saving-changes) |
| Agents            | The fifteen actions an agent can call, with the same inputs, results and errors                            | [Agents](/docs/agents)                            |
| `Root`            | Its props have the same names, types and defaults                                                          | [`Root`](/docs/api/react#root)                    |
| A view's strategy | `getRange`, `navigate`, `getTitle` and `project`, and the engine's projections, such as `projectMonth`     | [Custom views](/docs/views/custom-views#strategy) |
| CSS hooks         | Each part renders the same `data-calendar-part` attribute, so a selector written for one matches the other | [Components](/docs/api/react#components)          |

## What differs

|                               | React                                                             | Solid                                                                                         |
| ----------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Status                        | Complete                                                          | Preview                                                                                       |
| Framework version             | React 19                                                          | SolidJS 2.0                                                                                   |
| Packages you install          | `@moltenship/calendar`, `@ui-sdk/core`, `@ui-sdk/react`           | `@moltenship/calendar-solid`, `@moltenship/calendar-core`, `@ui-sdk/core`, `@ui-sdk/solid`    |
| Parts                         | The ten on the right, plus `Event` and `Announcer`                | `Root`, `Frame`, `Toolbar`, `Title`, three triggers, `ViewSwitcher`, `Viewport`, `ActiveView` |
| Hooks                         | Return values                                                     | Return accessors. Only the hooks that read state, meta, the range and the projection          |
| Ready-made views              | The registry's views, in shadcn/ui with Tailwind CSS or in StyleX | None. You write each view's `Renderer`                                                        |
| Keyboard navigation in a view | Yes                                                               | Not yet                                                                                       |
| Drag, resize and create       | Yes, with a mouse, a pen or touch                                 | Not yet. Your own controls call `actions.proposeEventChange`                                  |
| Undo and redo                 | `useCalendarHistory` and its shortcuts                            | Not yet                                                                                       |
| Screen reader announcements   | `Calendar.Announcer`                                              | Not yet                                                                                       |
| Testing package               | `@moltenship/calendar-testing`                                    | None                                                                                          |
| Agent bridge                  | `@ui-sdk/react/agent`                                             | `@ui-sdk/solid/agent`                                                                         |

[Solid](/docs/api/solid#what-isnt-in-it-yet) lists every missing hook by name.

## Which pages apply to Solid

There is one set of pages for both frameworks. Until the Solid integration has the rest, read them
from a Solid app like this:

| Section       | In a Solid app                                                                                                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Get started   | [Installation](/docs/installation#solid) covers both frameworks. The [Quick start](/docs/quick-start) uses the registry's React views, so follow [A calendar](/docs/api/solid#a-calendar) instead       |
| Concepts      | All six pages apply. The parts in [Anatomy](/docs/concepts/anatomy) that come from the registry, such as `MiniMonth`, are React source                                                                  |
| Views         | The view pages document React source. [Custom views](/docs/views/custom-views) applies, with a Solid component as the `Renderer`                                                                        |
| Interactions  | Saving, pending changes and policies apply. The drag, resize and create gestures don't exist yet                                                                                                        |
| Undo and redo | React only today                                                                                                                                                                                        |
| Availability  | `Root` takes `availability` and `resources`, and policies read them. The hooks that hand them to a view don't exist yet                                                                                 |
| Annotations   | `Root` takes `annotations`. The hook that hands them to a view doesn't exist yet                                                                                                                        |
| Accessibility | The keyboard map and the announcements describe React                                                                                                                                                   |
| Testing       | React only                                                                                                                                                                                              |
| Styling       | The tokens style the registry's React views                                                                                                                                                             |
| Agents        | Every page applies. Import the bridge from `@ui-sdk/solid/agent` where a sample imports `@ui-sdk/react/agent`                                                                                           |
| API reference | [Solid](/docs/api/solid) replaces [React components and hooks](/docs/api/react). The pages under "Engine and state" apply, except the pointer layer in [Event changes](/docs/api/changes#pointer-layer) |

## Start in React

1. [Install](/docs/installation) `@moltenship/calendar` and its peer dependencies.
2. Follow the [Quick start](/docs/quick-start) to a calendar with week, day, month and agenda views.
3. Save edits as [Interactions](/docs/interactions) shows.

## Start in Solid

1. [Install](/docs/installation#solid) `@moltenship/calendar-solid` and set up the Solid compiler.
2. Build [a calendar](/docs/api/solid#a-calendar) with a view you write.
3. Read [Differences from React](/docs/api/solid#differences-from-react) before you copy a sample
   from another page.

The repository's [`apps/demo-solid`](https://github.com/Moltenship/time/tree/main/apps/demo-solid)
is a running Solid calendar with a month grid, an agenda and an agent panel.

## Other frameworks

Time has no integration for Vue, Svelte, Angular or any framework other than these two. An
integration is written on `@moltenship/calendar-primitives`, whose API is unsettled. See
[Primitives](/docs/api/primitives).
