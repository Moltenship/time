title: React and Solid
description: What the React and SolidJS 2 integrations share, what each one has today, and what's coming for Solid.
---

Time's engine is in packages that import no UI framework. An integration package renders it in
one framework. There are two integrations, and each has its own docs: the select at the top of the
sidebar switches between them and keeps you on the same page where both have it. React's
integration is complete, and SolidJS 2's is a preview.

<Callout type="warn" title="Solid is a preview">
  `@moltenship/calendar-solid` has the parts and hooks React's integration has, keyboard navigation,
  dragging, drafts and undo included. Of the registry's views it has the week and day, the month,
  the year and the agenda, with the toolbar and the mini month, so far. The week and day show events
  but don't edit them yet. It has no testing package yet, so you write the other views. Its API can
  change in any release before 2.0.0.
</Callout>

## The layers

```text
views         React or Solid source from the registry, or components you write
integration   @moltenship/calendar (React)       @moltenship/calendar-solid (Solid)
calendar      @moltenship/calendar-primitives    state, actions, what an agent can call
engine        @moltenship/calendar-core          events, time zones, layout, changes, policies
              @moltenship/calendar-temporal
```

The engine and the calendar layer import neither React nor Solid. Each integration is a thin
package over them. It renders the parts and binds state to its framework's reactivity. The React
and Solid integrations don't import each other.

The calendar layer also holds the logic for keyboard navigation, roving focus, gesture drafts and
undo history, and `@moltenship/calendar-dnd`, the pointer layer, imports no framework. Both
integrations bind all of them, so a key or a drag does the same thing in both.

## What is the same

These work the same in both frameworks, because they run below the integration:

| Topic             | What both frameworks share                                                                                 | Read                                               |
| ----------------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| Events            | `defineEventAdapter`, validation, snapshots and queries                                                    | [Events and adapters](/docs/concepts/events)       |
| Time              | `Temporal` values, timed, all-day and floating events, time zones and daylight saving time                 | [Time and time zones](/docs/concepts/time)         |
| State             | The six state values, controlled and uncontrolled props, change handlers, and `createCalendarStore`        | [State](/docs/concepts/state)                      |
| Recurrence        | `@moltenship/calendar-recurrence` turns series into ordinary events before the calendar sees them          | [Series and occurrences](/docs/recurrence/model)   |
| Changes           | Proposals, `onEventChange`, `onEventChangeResult`, policies and pending changes                            | [Interactions](/docs/interactions#saving-changes)  |
| Undo history      | `createEventHistory` records results, and `useCalendarHistory` takes them back                             | [Undo and redo](/docs/undo-redo)                   |
| Keyboard          | The keys, roving focus and keyboard move, resize and create, through `useCalendarKeyboard`                 | [Keyboard](/docs/accessibility#keyboard)           |
| Pointer gestures  | Drag, resize and create with a mouse, a pen or touch, through `useCalendarPointer`                         | [Pointer layer](/docs/api/changes#pointer-layer)   |
| Announcements     | `Announcer` and the messages a screen reader hears                                                         | [Announcements](/docs/accessibility#announcements) |

## What differs

|                               | React                                                             | Solid                                                                                                                 |
| ----------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Status                        | Complete                                                          | Preview                                                                                                               |
| Framework version             | React 19                                                          | SolidJS 2.0                                                                                                           |
| Packages you install          | `@moltenship/calendar`, `@ui-sdk/core`, `@ui-sdk/react`           | `@moltenship/calendar-solid`, `@ui-sdk/core`, `@ui-sdk/solid`                                                         |
| Parts                         | `Root`, the structural parts, `Event` and `Announcer`             | The same parts                                                                                                        |
| Hooks                         | Every hook, returning values                                      | The same hooks: accessors for state, refs from `useCalendarKeyboard` and `useCalendarPointer`                         |
| Ready-made views              | The registry's views, in shadcn/ui with Tailwind CSS or in StyleX | The week and day, month, year, agenda, toolbar and mini month, in Tailwind CSS. You write the other views' `Renderer` |
| Keyboard navigation in a view | Yes                                                               | Yes, in the registry's views and in a view you write                                                                  |
| Drag, resize and create       | Yes, with a mouse, a pen or touch                                 | Yes, in the registry's month and in a view you write                                                                  |
| Undo and redo                 | `useCalendarHistory`, its shortcuts and the registry's toast      | The same, with the registry's toast                                                                                   |
| Screen reader announcements   | `Calendar.Announcer`                                              | `Calendar.Announcer`                                                                                                  |
| Server rendering              | Yes                                                               | Yes, with `renderToString` and `hydrate`                                                                              |
| Testing package               | `@moltenship/calendar-testing`                                    | None. That package has React as a peer dependency                                                                     |
| Agent bridge                  | `@ui-sdk/react/agent`                                             | `@ui-sdk/solid/agent`                                                                                                 |

## What's coming

Solid doesn't have these yet:

| Missing           | In React it's                                                        |
| ----------------- | -------------------------------------------------------------------- |
| Ready-made views  | The registry's scrolling and resource views, which are React source  |
| A testing package | `@moltenship/calendar-testing`, which is React only                  |
| A dnd-kit adapter | `@moltenship/calendar-dnd-kit`, which has React as a peer dependency |

The views are the next work. The registry gets Solid versions of its items, installed with the
same `shadcn add` command. The agenda, the toolbar, the mini month, the controls kit, the month view,
the year view, the recurring-event dialog and the undo toast came first. The week and day views show events, and
editing them by keyboard and pointer comes next. [Issue #279](https://github.com/Moltenship/time/issues/279) tracks each step.
The testing package and the dnd-kit adapter have no Solid plan yet.

Until the registry has a view in Solid, you write its `Renderer` with the package's hooks, as
[Custom views](/docs/solid/views/custom-views) does. The
[Solid demo](https://moltenship-time-demo.vercel.app/solid/) shows the registry's week, day, month, year and
agenda. Its month, year and agenda take keyboard navigation, dragging and undo. Its source is the repository's
[`apps/demo-solid`](https://github.com/Moltenship/time/tree/main/apps/demo-solid).

The Solid docs have no page on something Solid lacks. That is why the only ready-made views they
have pages on are the week and day, the month, the year and the agenda, beside the toolbar and the controls,
and they have none on StyleX, testing or the dnd-kit adapter.

## From React to Solid

The same calendar reads differently in the two frameworks in these places:

| In React                                     | In Solid                                                                                          |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Hooks return values                          | Hooks that read state return accessors: `state().view`, not `state.view`                          |
| `useCalendar()` returns plain objects        | `meta` and `state` are getters. Read them in JSX, a memo or an effect, and don't destructure them |
| A `Renderer` gets props you can destructure  | A `Renderer`'s props are getters: `props.projection`, read where it's used                        |
| `meta.refs` holds React refs                 | `meta.refs` holds accessors: `meta().refs.viewport()`                                             |
| `useCalendarKeyboard()` returns handlers     | It returns a ref, which binds `keydown` and `focusout` on the element itself                      |
| A cell's `onKeyDown` runs before the view's  | It runs after, since Solid delegates it. Listen natively from a ref to take a key first           |
| `useRovingFocus` listens for `focusin`       | It listens for `focus`, so a focus handler of yours hears `"focus"`                               |
| `Calendar.Event`'s children get a value      | They get an accessor, and stay rendered while the event changes                                   |
| A state change is visible on the next render | An accessor has the new value once Solid flushes: a microtask later, or after `flush()`           |
| `@moltenship/calendar` is the one package    | `@moltenship/calendar-solid` is the one package too: it re-exports the engine                     |
| The bridge is `@ui-sdk/react/agent`          | The bridge is `@ui-sdk/solid/agent`                                                               |

The state model, controlled and uncontrolled props, change handlers, `onEventChange` and
`onEventChangeResult`, policies, pending changes and every agent action are the same.

## Other frameworks

Time has no integration for Vue, Svelte, Angular or any framework other than these two. You'd write
one on `@moltenship/calendar-primitives`, and its API can still change.

See [Primitives](/docs/api/primitives).
