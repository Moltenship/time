Time's engine is in packages that import no UI framework. An integration package renders it in
one framework. There are two integrations. React is complete, and SolidJS 2 is a preview.

<Callout type="warn" title="Solid is a preview">
  `@moltenship/calendar-solid` has the parts and hooks React's integration has, keyboard navigation,
  dragging, drafts and undo included. It has no ready-made views and no testing package yet, so you
  write each view. Its API can change in any release before 2.0.0. The code samples on the other
  pages are React.
</Callout>

## The layers

```text
views         React source from the registry, or components you write
integration   @moltenship/calendar (React)       @moltenship/calendar-solid (Solid)
calendar      @moltenship/calendar-primitives    state, actions, what an agent can call
engine        @moltenship/calendar-core          events, time zones, layout, changes, policies
              @moltenship/calendar-temporal
```

The engine and the calendar layer import neither React nor Solid. Each integration is a thin
package over them. It renders the parts and binds state to its framework's reactivity. The React
and Solid integrations don't import each other.

The calendar layer also holds the logic for keyboard navigation, roving focus, gesture drafts and
undo history, and `@moltenship/calendar-dnd`, the pointer layer, imports no framework. Both
integrations bind all of them, so a key or a drag does the same thing in both.

## What is the same

These work the same in both frameworks, because they run below the integration:

| Topic             | What both frameworks share                                                                                 | Read                                               |
| ----------------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| Events            | `defineEventAdapter`, validation, snapshots and queries                                                    | [Events and adapters](/docs/concepts/events)       |
| Time              | `Temporal` values, timed, all-day and floating events, time zones and daylight saving time                 | [Time and time zones](/docs/concepts/time)         |
| State             | The six state values, controlled and uncontrolled props, change handlers, and `createCalendarStore`        | [State](/docs/concepts/state)                      |
| Recurrence        | `@moltenship/calendar-recurrence` turns series into ordinary events before the calendar sees them          | [Recurring events](/docs/concepts/recurrence)      |

| Undo history      | `createEventHistory` records results, and `useCalendarHistory` takes them back                             | [Undo and redo](/docs/undo-redo)                   |
| Keyboard          | The keys, roving focus and keyboard move, resize and create, through `useCalendarKeyboard`                 | [Keyboard](/docs/accessibility#keyboard)           |

## What differs

|                               | React                                                             | Solid                                                                                           |
| ----------------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Status                        | Complete                                                          | Preview                                                                                         |
| Framework version             | React 19                                                          | SolidJS 2.0                                                                                     |
| Packages you install          | `@moltenship/calendar`, `@ui-sdk/core`, `@ui-sdk/react`           | `@moltenship/calendar-solid`, `@moltenship/calendar-core`, `@ui-sdk/core`, `@ui-sdk/solid`      |
| Parts                         | `Root`, the structural parts, `Event` and `Announcer`             | The same parts                                                                                  |
| Hooks                         | Every hook, returning values                                      | The same hooks, returning accessors. `useCalendarKeyboard` and `useCalendarPointer` return refs |
| Ready-made views              | The registry's views, in shadcn/ui with Tailwind CSS or in StyleX | None. You write each view's `Renderer`                                                          |
| Keyboard navigation in a view | Yes                                                               | Yes, in a view you write                                                                        |
| Drag, resize and create       | Yes, with a mouse, a pen or touch                                 | Yes, in a view you write                                                                        |
| Undo and redo                 | `useCalendarHistory`, its shortcuts and the registry's toast      | `useCalendarHistory` and its shortcuts. No toast                                                |
| Screen reader announcements   | `Calendar.Announcer`                                              | `Calendar.Announcer`                                                                            |
| Server rendering              | Yes                                                               | Yes, with `renderToString` and `hydrate`                                                        |
| Testing package               | `@moltenship/calendar-testing`                                    | None. That package has React as a peer dependency                                               |
| Agent bridge                  | `@ui-sdk/react/agent`                                             | `@ui-sdk/solid/agent`                                                                           |

[Solid](/docs/api/solid#what-isnt-in-it-yet) lists what's missing.

## Start in React

1. [Install](/docs/installation) `@moltenship/calendar` and its peer dependencies.
2. Follow the [Quick start](/docs/quick-start) to a calendar with week, day, month and agenda views.
3. Save edits as [Interactions](/docs/interactions) shows.

## Start in Solid

1. [Install](/docs/installation#solid) `@moltenship/calendar-solid` and set up the Solid compiler.
2. Build [a calendar](/docs/api/solid#a-calendar) with a view you write.
3. Read [Differences from React](/docs/api/solid#differences-from-react) before you copy a sample
   from another page.

The [Solid demo](https://moltenship-time-demo.vercel.app/solid/) is a running Solid calendar with a
month grid and an agenda you can navigate with the keyboard and drag events in, undo and redo, and
an agent panel. Its switch opens the React demo and keeps the view and the date. Its source is the repository's
[`apps/demo-solid`](https://github.com/Moltenship/time/tree/main/apps/demo-solid).

## Other frameworks

Time has no integration for Vue, Svelte, Angular or any framework other than these two. You'd write
one on `@moltenship/calendar-primitives`, and its API can still change. See
[Primitives](/docs/api/primitives).
