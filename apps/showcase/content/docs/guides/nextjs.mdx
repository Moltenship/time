Time works with any React 19 framework that renders on the server. This guide uses the Next.js App
Router. The same rules apply elsewhere.

## Calendars are Client Components

Calendar state lives in React state, so `createCalendar`, `defineCalendarView`, and the components
are client-only. Put your calendar, its views, and `Root` in files that start with `"use client"`,
as the [Quick start](/docs/quick-start) does. Server Components can render those components and pass
them props.

The rest of `@moltenship/calendar` works on the server too. A Server Component can import the
Temporal helpers or build a snapshot, for example to filter events before sending them.

## Match the server and the browser

During server rendering and hydration, Time doesn't read the clock, the host time zone, or `window`.
Everything that affects the first render comes from props, so the server and the browser produce the
same markup as long as they get the same props. In practice:

- **Compute "now" once on the server** and pass it down, as `now` above. Calling
  `Temporal.Now.instant()` in a Client Component gives the server and the browser different values.
  Without `now`, anything that depends on the current time (a view's `today`, `useNow()`) is empty
  on the server and fills in after hydration.
- **Choose the time zone on the server**, for example from the user's profile or a cookie. The
  server's own zone is rarely the user's.
- **Pass the same `locale`** to both. Dates and times are formatted with `Intl`, which depends on it.

If you only learn the user's time zone in the browser, render the calendar after hydration, or pass
the zone as a controlled `timeZone` and update it once you know it.

## Element IDs

`Root` derives element IDs from React's `useId`, so they match between server and browser. If you
render several separate React roots on one page, give each a distinct `identifierPrefix` when you
create it (on both server and client), or pass an explicit `id` to each `Root`.
