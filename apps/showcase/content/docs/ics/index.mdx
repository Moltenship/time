`@moltenship/ics` reads iCalendar (RFC 5545), the text format of calendar feeds, invitations and
exports from Google Calendar, Outlook, iCloud and most other calendar apps. ICS text goes in.
Calendars, events, to-dos, journals, free/busy and time zones come out, with dates and times as
`Temporal` values and every problem in the text listed with its line.

## Use it without the calendar

The package imports no other Moltenship package, no UI framework and no dependency. It runs
wherever `Temporal` does: in a browser, on a server, in a worker or in a script. An app that never
renders a calendar can use it to read a feed, check an upload or convert an export.

`@moltenship/calendar` doesn't re-export it, so install it by its own name.

## Parse a calendar

`parseIcs` takes the text and returns its calendars. `getEventEnd` works out when an event ends,
from its `DTEND` or its `DURATION`:

<include meta='title="describe-events.ts"'>../../examples/ics-first.ts#first</include>

`describeEvents(text)` returns these lines:

```text
Planning: 2026-10-12T09:00:00+02:00[Europe/Berlin] to 2026-10-12T09:45:00+02:00[Europe/Berlin]
Offsite: 2026-10-15 to 2026-10-17
```

The first event names a time zone, so its start is a `Temporal.ZonedDateTime`. The second is an
all-day event, so its start is a `Temporal.PlainDate`, and its end is the day after its last day,
as the file wrote it. A start's `kind` says which of five shapes the file used, and
[Dates and times](/docs/ics/reference#dates-and-times) lists them.

## What it does with bad text

Parsing is lenient. The parser keeps what it can read, skips a component it can't type, such as an
event without `UID` or `DTSTART`, and reports each problem in `issues` with its line. Bad text
never throws. With `strict: true`, an error throws an `IcsParseError` instead.
[Read an .ics file](/docs/ics/import) shows both ways.

## What it doesn't do

- **It doesn't expand recurring events.** A rule is parsed into an `IcsRecurrenceRule`, and its
  occurrences aren't listed. [`@moltenship/calendar-recurrence`](/docs/recurrence) lists them.
- **It doesn't write ICS from typed objects.** `stringifyIcsComponents` writes a syntax tree you
  build yourself.
- **It doesn't read bytes.** `parseIcs` takes a string, so decode the bytes as UTF-8 first.
