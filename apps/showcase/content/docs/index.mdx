Moltenship Time handles the hard parts of a calendar: dates, time zones, navigation, calendar
state, and fast event lookups. You write the markup. Your events stay in the shape your app already
uses, and Time reads them through a small adapter.

<Callout type="warn" title="Pre-1.0">
  Time is in active development and not published to npm yet. Everything on these pages works today,
  but expect breaking changes before 1.0. Built-in month, week, day, and agenda views are being
  built now. Until they land, you write your own views.
</Callout>

## Who it's for

Time is for React developers building scheduling screens (bookings, rooms, shifts, team calendars)
who want to:

- render the calendar with their own components and design system,
- keep their existing event data and API,
- get time zones and daylight saving time right without writing that math themselves.

If you need a styled, drop-in calendar today, Time isn't there yet.

## What you get today

- **Your data, read through an adapter.** You describe how to read an ID, title, and time range
  from your records. TypeScript keeps your record and ID types all the way through.
- **Three kinds of time.** Timed events use `Temporal.Instant`, all-day events use
  `Temporal.PlainDate`, and floating events use `Temporal.PlainDateTime`. No `Date` objects.
- **Time zone and DST handling.** Days that are 23 or 25 hours long and skipped or repeated hours
  are handled for you.
- **Indexed event lookups.** Events are validated and indexed once, so range and resource queries
  don't scan every event.
- **Views as small, typed functions.** A view is a strategy (visible dates, navigation, title, and
  which events to show) plus a component that draws them. Time runs the strategy and caches the
  result.
- **Controlled or uncontrolled state.** The visible date, view, time zone, selection, and focus can
  each be owned by the calendar or by your app.
- **Unstyled components.** `Root`, `Toolbar`, previous/next/today buttons, `Title`, `ViewSwitcher`,
  and `ActiveView` render plain elements with `data-calendar-part` attributes you can style.
- **Styled parts to copy.** A theme with calendar tokens and an event color palette, plus a toolbar,
  view switcher, event chip, and mini month, as shadcn/ui-style source you own. See
  [Theming](/docs/theming).
- **Server rendering.** During server rendering, Time doesn't read the clock, the host time zone, or
  `window`, so the server and the browser render the same markup from the same props.
