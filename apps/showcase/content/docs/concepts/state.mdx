`Root` keeps six values:

| Value                 | Type                   | Meaning                                     |
| --------------------- | ---------------------- | ------------------------------------------- |
| `view`                | one of your view names | The active view                             |
| `anchorDate`          | `Temporal.PlainDate`   | The date the visible range is built around  |
| `timeZone`            | `string` (IANA name)   | The zone timed events are shown in          |
| `selection`           | your type, or `null`   | What the user selected                      |
| `focus`               | your type, or `null`   | What has keyboard focus inside the calendar |
| `expandedResourceIds` | array of resource IDs  | Which resource groups are expanded          |

Each value can be **uncontrolled** (the calendar owns it) or **controlled** (your app owns it),
independently of the others.

## Uncontrolled

Pass a `default` prop and the calendar manages the value from then on. Defaults are read once, when
`Root` mounts.

<React>

```tsx
<Calendar.Root
  events={meetings}
  defaultView="day"
  defaultAnchorDate={Temporal.PlainDate.from("2026-10-08")}
  defaultTimeZone="Europe/Berlin"
  locale="en-US"
  weekRules={weekRules}
>
  <Calendar.ActiveView />
</Calendar.Root>
```

</React>

## Controlled

Pass the value and a change handler. The calendar never changes a controlled value itself. When the
user clicks Next, it calls your handler with the new value, and you decide whether to store it.

The props follow one pattern:

| Uncontrolled                 | Controlled            | Handler                       |
| ---------------------------- | --------------------- | ----------------------------- |
| `defaultView`                | `view`                | `onViewChange`                |
| `defaultAnchorDate`          | `anchorDate`          | `onAnchorDateChange`          |
| `defaultTimeZone`            | `timeZone`            | `onTimeZoneChange`            |
| `defaultSelection`           | `selection`           | `onSelectionChange`           |
| `defaultFocus`               | `focus`               | `onFocusChange`               |
| `defaultExpandedResourceIds` | `expandedResourceIds` | `onExpandedResourceIdsChange` |

A few rules:

- `undefined` means uncontrolled. To control `selection` or `focus` with nothing selected, pass
  `null`.
- Handlers also run for uncontrolled values, after the calendar updates them. The second argument
  says what changed, why, and who asked. See [what a handler hears](#what-a-handler-hears).
- If you haven't applied a change the calendar asked for, the handler also hears a later request
  for the value you have. For example, Today after a scroll you deferred. Apply the latest value
  you were given, and you'll drop the earlier change.
- `Root` needs a date, a time zone, and a view on its first render. The view can come from
  `defaultView`, `view`, or the first registered view. If one is missing, `Root` throws
  `calendar-root-requires-anchor-date`, `calendar-root-requires-time-zone`, or
  `calendar-root-requires-view`.

## What a handler hears

Every change handler gets the new value and a detail:

| Field        | Type               | Meaning                                                                       |
| ------------ | ------------------ | ----------------------------------------------------------------------------- |
| `slice`      | `string`           | Which value changed, such as `"view"` or `"anchorDate"`                       |
| `previous`   | the value's type   | The value before the change                                                   |
| `controlled` | `boolean`          | Whether a prop controls the value                                             |
| `reason`     | `string`           | Why it changed. See below                                                     |
| `source`     | `string`           | Who caused it. See below                                                      |
| `event`      | `Event`, or absent | The DOM event behind it, such as a button's click. Absent for code and agents |
| `cancel()`   | function           | Stops the change. An uncontrolled value goes back to `previous`               |
| `canceled`   | `boolean`          | Whether `cancel()` was called                                                 |

`reason` is one of:

- `"next-press"`, `"previous-press"` or `"today-press"`: a press of `Calendar.NextTrigger`,
  `Calendar.PreviousTrigger` or `Calendar.TodayTrigger`.
- `"input-change"`: a choice in `Calendar.ViewSwitcher`.
- `"keyboard-navigation"`: a key in a view that moves focus or the visible range, such as an
  arrow key or Page Down.
- `"focus-change"`: focus a person moved onto a cell or an event, by clicking it or tabbing to it.
- `"resource-toggle"`: a resource expanded or collapsed.
- `"imperative"`: an action called from code, such as `actions.setView("month")`. It's also the
  reason for anything an [agent](/docs/agents) does.

`source` is one of `"mouse"`, `"touch"`, `"pen"`, `"keyboard"`, `"virtual"`, `"agent"` or
`"programmatic"`. `"keyboard"` is a person's keys, on a toolbar button and in a view: arrow-key
navigation, moving focus and expanding a resource report it. `"virtual"` is a click with no
pointer or key behind it, which may come from assistive technology. `"agent"` is an AI agent
acting through the [agent bridge](/docs/agents/connect), and anything its step causes.
`"programmatic"` is your own code.

`cancel()` puts an uncontrolled value back as it was. For a controlled value it does nothing you
couldn't do yourself: the value changes only when you store it.

Every action takes the same options as its last argument: `{ event?, reason?, source? }`.
Without them, a call from your code reads `reason: "imperative"` and `source: "programmatic"`.

## Reading and changing state

Any component inside `Root` can use the hooks on your calendar<Solid>. A hook that reads a value returns an accessor, so call it where you use the value: `state().view`</Solid>:

- `useCalendarState()` returns all six values.
- `useCalendarSelector(selector)` returns one derived value<React> and re-renders only when it changes</React><Solid>, and its readers run again only when it changes</Solid>.
- `useCalendarActions()` returns `setView`, `setAnchorDate`, `setTimeZone`, `setSelection`,
  `setFocus`, `setExpandedResourceIds`, `navigateNext`, `navigatePrevious`, `navigateToday`,
  `proposeEventChange`, and `checkEventChange`.
- `useCalendarMeta()` returns everything else: the event snapshot, resources, the environment, the
  active view and the registered views, diagnostics, the instance ID, and element IDs and refs.
- `useCalendar()` returns `state`, `actions`, and `meta` together.
- `useVisibleRange()` and `useViewProjection()` return what the active view shows. See
  [Custom views](/docs/views/custom-views#reading-the-view-from-other-components).

## Selection and focus types

You choose the shape of `selection` and `focus`. Pass their types as the third and fourth type
arguments of `createCalendar`, after the event and resource types. Time stores the values as they
are.
