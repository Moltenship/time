Calendar,
without debt.

Time is a Temporal-native, React 19 calendar system built on five principles: application data remains authoritative; performance comes from indexed projections and bounded rendering rather than later optimization; every interaction is controllable and accessible; consumers own the visual source while upgradeable engines own difficult algorithms; and public contracts stay typed, deterministic, composable, and SSR-safe.

Repository Moltenship/time
Primary install @moltenship/calendar
Render target React 19 + SSR
Data target 10k events · 500 resources
01 / 14

The decisions that remove ambiguity.

A calendar becomes unmaintainable when ownership, interval semantics, and extension points remain implied. These are contracts, not preferences.
Distribution thesis Users own every visible line of source. Versioned packages own indexes, layouts, state contracts, and interaction semantics that should receive fixes without a copy-paste migration.
A

External facts

Events, resources, permissions, fetching, and persistence stay with the application. The calendar emits proposals.
B

Half-open time

All intervals are [start, end). Adjacent events are adjacent—not overlapping by accident.
C

Temporal only

Instant, PlainDate, and PlainDateTime encode distinct meanings. No Date and no bundled polyfill.
D

Explicit views

Month, week, day, list, and both resource shapes are definitions—not boolean branches inside one component.
E

Private machinery

Jotai, dnd-kit, interval trees, caches, and DOM structure never become accidental public APIs.
F

Evidence gates

Performance, SSR, accessibility, and browser claims exist only when a corresponding gate passes.

04 / 14

Three meanings of “when.”

A timezone bug begins when an instant, a local wall time, and a calendar date share one loose type. The event union keeps them apart. 
type CalendarEventInterval =
  | {
      kind: "timed"
      start: Temporal.Instant
      end: Temporal.Instant
      sourceTimeZone?: string
    }
  | {
      kind: "all-day"
      start: Temporal.PlainDate
      end: Temporal.PlainDate
    }
  | {
      kind: "floating"
      start: Temporal.PlainDateTime
      end: Temporal.PlainDateTime
    }

// Every interval is [start, end).

Timed

Instant
An absolute moment. Project it into the calendar display zone; retain source zone only for editing context.

All day

PlainDate
A date interval independent of wall-clock duration. One day ends at the next date, exclusively.

Floating

PlainDateTime
A wall time that does not move between zones—useful for domain-local schedules and templates.
DST
Day and week axes show wall time. Gaps and folds remain explicit geometry. The default Temporal disambiguation is compatible; policies may reject it, and automatic shifts are included in the transaction and announcement.
TypeScript
The current TypeScript compiler with lib: ["ESNext"] supplies the ambient Temporal namespace. Packages use the global directly and neither depend on nor re-export a separate Temporal type package.
05 / 14

From fetched record to bounded pixels.

A new event snapshot pays one normalization cost. Everything after it is a query, projection, or cached layout—never a scan from every cell.
01EventsImmutable array or external event source.
02AdapterApplication records become typed calendar intervals.
03IndexesBy ID, time interval, date interval, resource and revision.
04QueryVisible range and resource slice only.
05ProjectDisplay zone, day splits, resource fragments.
06LayoutAll-day lanes, timed overlaps, logical geometry.
07WindowVirtualized axes and bounded overscan.
08RenderStable typed models enter editable registry source.
Invalidation rule A selection change cannot rebuild the event index. A pointer move cannot rerun projection. A color change cannot recalculate geometry.

08 / 14

Propose. Validate. Confirm.

The calendar never mutates an application event. Pointer, keyboard, touch, and an edit form all produce one semantic transaction.
01BeginPointer, touch, keyboard or command.
02MapGeometry to date, time and resource.
03PolicySnap, bounds, hours, overlap, app rules.
04PreviewTransform without mutating source data.
05EmitTyped original and proposed placement.
06OptimisticSmall pending patch while persistence settles.
07ConfirmNew snapshot wins; rejection rolls back.
INPUT PARITY
dnd-kit is an adapter, not the interaction model. Every create, move and resize command has keyboard and explicit-action equivalents. Raw dnd-kit events never enter application callbacks.

11 / 14

A theme contract, not a theme prison.

The registry installs ordinary React and Tailwind source. Engine packages ship no mandatory stylesheet and know nothing about event color.

Inherited shadcn tokens

--background--foreground--card--primary--secondary--muted--accent--destructive--border--ring--radius

Calendar semantic tokens

--calendar-grid--calendar-axis--calendar-today--calendar-now--calendar-selection--calendar-business-hours--calendar-event--calendar-invalid
Visual structure is composed with children. Typed render callbacks exist only where the calendar must hand event or fragment data back to consumer source. View variants are explicit components—not boolean prop combinations.

14 / 14

The merge checklist.

Features may change. These invariants protect the shape of the library while they do.
External events remain authoritative.
Every interval is typed and half-open.
No implicit host timezone or render-time now.
Core imports no React, DOM, Jotai, dnd-kit or CSS.
No total-event or total-resource work inside a frame.
Pointer actions have keyboard and explicit equivalents.
Controlled state is never mirrored through an effect.
Custom views use public contracts only.
Registry source uses semantic tokens and stays editable.
SSR markup is deterministic by construction.
Claims carry performance, browser and accessibility evidence.
No boolean-prop matrix and no god file.

The calendar is not the component.

It is a set of stable time semantics, indexed data projections, view strategies, transactions, and human interaction contracts. The component is the source users install on top—and are free to make entirely their own.
